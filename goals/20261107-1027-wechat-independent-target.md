# TGT01：微信独立选择原生会话

## 目标与已确认行为

本人于 2026-11-07 明确要求实施：微信的普通消息只跟随微信显式选择的准确 Codex thread；桌面窗口焦点或同一终端从 A 切至 B 不被动改变微信目标。若原 A 无法可靠核验或原生接入失败，微信收到明确提示；不复制历史、另建替代会话、猜测目标或重放未知输入。

用户所称 session 对应一段独立对话；实现以 thread ID 标识，不能混用原生 sessionId 根身份。

## 范围、背景和实现边界

- 先修订 AGENTS.md 的产品契约，再修改绑定复验、会话目录和必要的错误提示与测试，最后同步当前使用说明、命令契约、调研结论和 ROADMAP。
- 入口：src/wx_clawbot/sessions.py、catalog.py、controller.py、hosts/visible.py、agents/codex.py、agents/queue.py；测试入口为 tests/test_sessions.py、test_catalog.py、test_controller.py 及显式 tests/integration/。
- 保留首次发现的页脚身份关联和可见启动握手；本次不承诺任意存档会话发现、不移除首次发现的显示依赖，不修改 Codex 全局状态栏、标题、Hooks、认证或模型。
- 已核验绑定保持原终端／进程、运行时、thread、native session 和 cwd；刷新目录时保留仍有效的旧绑定，同时可发现桌面新 B。不得将原 A 重新解释为 B。
- 进程退出／重用、原生换代、thread 卸载、身份或目录变化继续拒绝。恢复不能重建来源证据时明确通知，不凭 ID 恢复资格。
- 沿用原生队列、任务接收时冻结目标、仓库准入、订阅和 unknown 不重放。无新依赖、无数据库迁移。
- 真实验证只用自建专用测试终端与项目；不操作微信客户端，不发送微信测试消息，不动用户工作会话或生产账本。提交、推送及本机部署不在本次授权内。

## 检查点与自测

1. 修订规范并核对协议／现有实现，记录可验证的独立绑定条件；施工清单落盘。
2. 用回归测试复现桌面切至 B 导致原 A 失效，再实现准确绑定独立复验与目录保留；首次绑定仍拒绝缺失／冲突页脚。
3. 验证微信 focus／单次发送／刷新／受管复用语义、失败提示、原目标冻结与订阅独立性；不更改原消息接收顺序。
4. 在专用原生 TUI 中实际建立 A、切至 B，核验同进程不同 thread，再通过候选执行链向 A 提交唯一只读任务；检查准确 A turn／client ID／终态和上下文，B 不收到该输入。随后显式选择 B 验证切换，检查终端退出后的拒绝提示与零提交；清理仅限确认归属且空闲的自有资源。
5. 运行项目统一检查 scripts/check.py，测试数量非零；检查文档链接、diff、依赖、编译和公开内容。

## 验收标准

- A→B 后微信选中 A 不变，准确 A 仍可接入时任务在原 A 执行，不向 B 串投、不新建 thread、不复制历史。
- 刷新／准入发现不丢弃可核验 A；显式选择才改变目标，已有任务不迁移。
- 首次未证明关联、进程失效、runtime／session／cwd／thread 身份异常时不派发，微信输出说明；原生提交未知不重试。
- 真实测试必须提供版本、步骤、准确原生关联与终态的脱敏证据；不能用模拟测试替代。无法验证的场景明确保持未验收。
- 项目必要检查通过，受影响文档与代码一致；生产配置／服务／用户会话保持。
