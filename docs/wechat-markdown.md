# 微信出站 Markdown 排版

本文描述源码中已实现的出站处理规则。当前版本见 [ROADMAP](../ROADMAP.md)，历史客户端验收见[验证记录](validation/wechat-markdown.md)，不把离线结果当作手机或 Mac 显示、复制已经通过。

本次交付目标客户端为 Android 微信 8.0.80。本人已于 2026-10-31 后置 Mac 完整排版要求；Mac 4.1.15.22 已知复杂围栏、缩进载体和括号链接缺陷仍保留，不能据简单代码或字段列表通过宣称完整兼容。Android 必要格式与真实任务已按当时范围验收，具体证据见验证记录；不承诺未知客户端形态。

MD01 当时交付的列表兼容修正版完成 512 项离线回归；当前版本与部署以 ROADMAP 为准，以下描述其格式证据范围。S01 静态混合样例的行内缺失／移位已恢复；S02 用明确列表项标签关联续段与独立代码，在 Android 显示完整，37 字节标记保护复制精确，另一嵌套围栏代码 56 字节复制也精确。直接带代码的简单顶层列表项采用这种兼容；含子列表、引用或未知块的复杂项保留原结构。最终版本的真实文字五段、单图分析、准确微信追问及日常恢复均已核对；证据来源和仍受限的客户端形态见验证记录。

## 格式与兼容规则

| 格式 | 出站行为 | 客户端边界 |
| --- | --- | --- |
| 换行、段落、空段 | 明确的普通说明分行转成段落边界；既有空段、代码及受保护字面位置的换行和空格保留 | Android 支持标准 LF；Mac 会合并单 LF／双空格硬换行，改用段落兼容。跨行强调及复杂容器保留源语法，尚不能保证 Mac 分行；不全局替换 U+2028 |
| 加粗 | 保留 `**重点**` 及其语义范围 | 本人已确认 Android 原始对照明显加粗 |
| 标题 | H1 至 H6 转成加粗的 `【一级标题】` 至 `【六级标题】` 标记，正文保留原有强调；支持 ATX 和 Setext | 本人接受显式级别兼容；不承诺原生六级字号 |
| 列表、引用 | 保留编号、列表层级和引用源标记；直接含代码的简单顶层列表项将续段／代码按明确所属项另列，代码独立分段，其他复杂项保留源结构 | S02 明确所属关系／续段／代码显示及 37 字节复制通过；最终真实结果的多层普通列表、引用及续段已有 Android 截图证据 |
| 链接 | 保留显示文字、目标地址、编码、参数和片段；引用式链接先展开。含括号的 HTTPS 目标在普通段落／列表／引用中单列完整地址；当前统一使用标准自动链接 `<URI>`，标题／强调内保留显示完整地址的自动链接，标题元数据以字面代码保留。未用／重复定义按原文保留 | 本人已确认 L01 原地址完整、L02 可点击；最终真实混合结果的完整自动链接已观察。代码、图片语法、引号字面值和错误不作这种转换，不打开链接或改写目标 |
| 行内代码 | 按解析器识别的源范围保护，含多重反引号和跨行内容 | 超长不可分单元显式使用保真片段，不冒充完整可复制块 |
| 围栏代码 | 原始代码字符、语言、缩进、LF／CRLF、空行与尾随空格保留；简单波浪围栏仅在无反引号冲突时转三反引号，长代码按完整行闭合／重开 | Android 37／56 字节样例与最终结果同文且实际精确复制，Mac 简单 Python 与跨段长代码也有精确复制证据；内嵌围栏的独立四反引号与波浪载体分别只复制 33／37、25／37 字节，仍未支持无损复制。修补不加入代码正文，不能凭离线正确认定客户端通过 |
| 缩进代码 | 转成围栏代码，保留源文所有前导空格，包括原有结构缩进 | 采用源文本保真，不自动移除四个缩进空格；列表／引用的容器标记保持结构 |
| 扩展强调 | 英文斜体保留；遇中文斜体或删除线时保留原文标记，并独立加入一次样式兼容说明 | 不在强调内部插入标签，不把普通字形冒充原生斜体或删除线 |
| 简单表格 | 顶层普通表头转为明确的“表格（字段列表）”，逐行保留列名、顺序、单元格代码、转义竖线及空值；重复列名保留，复杂表头／容器表格保留源结构 | C02 的 Android 三行完整已由本人确认，Mac 三行对应有照片证据；此修正已随 v4 加载。混合结果的其他内容移位仍单独保留失败。展开超限时明示保留表格源文，不静默丢列 |
| 分隔线、任务列表 | 保留分组结构及 `[ ]`／`[x]` 状态 | 任务列表为静态显示，不产生勾选操作 |

正文中文排版仅处理可识别片段；代码、引号字面值、URL、路径、命令和原生错误保留。复杂或过长的疑似代码片段采取保守保留。HTML、图片和链接不会由渲染器执行、下载或打开；数学公式、Mermaid 等不新增图形渲染能力。

## 长消息与复制

优先在段落、标题、列表项、引用和代码块的边界拆分；每个最终 payload 包含来源／段号、重复定义及围栏修补，并接受现有 8000 字符本地校验。字符数与 UTF-8 字节数分别计算，不将本地字符限额当作服务端字节容量保证。

单个 URL、行内代码、代码行、复杂块或围栏本身无法放入一条时，使用明确的“原文片段”说明及独立字面代码块。每段有确定的源切片及展示修补记录，离线核对按这些记录逐字重建；不能把所有反引号或空白笼统删除。此类片段不保证单段可作为完整链接或整段代码使用，完整内容以原终端为准。

普通代码的 CRLF 和特殊 Unicode 数据不作全局替换。单独的 CR 使用明确字面片段兼容，传输仍保留该字符，但不承诺客户端复制不归一化行尾。超深、未知或未闭合语法保留可读源文，解析深度有界；本地没有执行语义。兼容标记扩张后仍受既定结果限额约束，超限明示保留首尾，保留末尾原生错误；不会把截断当作完整结果。

## 入账、历史与运行边界

新内容只在入账前渲染和分段。命令、观察结果传递已准备的片段，账本直接冻结；普通进展／交互提示和任务终态也走同一渲染规则。渲染在后台线程、数据库事务前完成；终态与新回执仍在同一事务写入。发送器只发送已冻结正文，不渲染历史，也不重新执行任务。

升级不迁移 schema，不重写旧 outbox 正文、摘要或投递记录；旧回执重试仍使用旧冻结文本。仅代码排版变化，不更改目标选择、宿主恢复、原生队列、审批裁决或单图入口。检查及加载新版按[运维说明](operations.md)执行，实际运行记录以验证文档为准。

## PERF01 性能边界

[PERF01](validation/performance-optimization.md)已在 `0.1.0` 为无适用语法的阶段增加保守快速返回，并将至少 65536 字符的渲染放入有截止和回收的临时子进程，小结果继续使用线程。每个消费者最多两个大结果子进程，事务外渲染，父进程精确附加前缀；没有跨任务大正文缓存。正式数据包含原版／候选 payload、分段、重建及实际子进程的字节对照。

ENG01 的当前执行边界为至少 32768 字符使用上述子进程，8192 至 32767 字符的线程渲染共享两槽，小型控制回执不等待批量结果槽位；具体结构见[架构](architecture-design.md)。这是 CPU 调度路径变化，源内容、保护范围和冻结结果语义保持。PERF01 的 65536 是当时测量基线，不追改成新阈值。

该实现已在本机加载，见[部署记录](validation/local-release.md)；它不改变上述客户端能力、容量和兼容策略，不重排旧 outbox，不声称重做了 Android／Mac 显示或复制验收。纯渲染计时与实际异步路径计时分别报告。PERF01 的显式 schema 4 索引升级是独立事项，不改变 MD01 当时不迁移账本的交付事实。
