# NCM01：0.169.0 设置读取与卸载验证

状态：专用原生验证及独立收尾核验通过。此记录限定实际连接的 0.169.0，以及下述关闭 TUI／跨连接归档两条路径；没有将结论扩写为所有版本、所有强制卸载方式或服务端条件式 resume。当前 Git 交付与验证时间见[机器摘要](native-settings-lifecycle.json)，项目进度见 [ROADMAP](../../ROADMAP.md)。

## 对象与方法

一个自有 iTerm2 窗口、两个明确命名的临时项目标签。通过可见启动回执、boot PID／启动代次、唯一原生握手、runtime／thread／native session／cwd 核对来源；各自一次启动标记 turn 完成，没有额外业务输入或设置修改。日常桥接与项目清单保持，无微信操作或测试消息。

被测代码来自独立非 editable 维护候选：内部版本元数据仍为 0.1.12，包源码与当前维护工作树一致，仅项目列表等价分支简化区别于已发布制品。它不是新发行版，也未替换本机已发布的 0.1.12。源码、wheel 与依赖锁摘要见机器记录。

使用三个连接区分订阅保持者、归档发起者及只读核验者。保持者对已核验的准确会话建立真实原生订阅；归档只作用这两个自有 thread，每个一次意图，异常不重放。读取直接调用产品的 CodexConnection.read_settings；不是合成原生响应。

## 实际结果

| 场景 | 实际动作与观察 | 结论 |
| --- | --- | --- |
| 关闭 TUI，保持原生订阅 | 两个自有终端在准确 idle／空队列后关闭；loaded 列表仍包含会话，设置读取与原快照一致 | 关闭终端本身不会在本次订阅条件下制造卸载 |
| 另一连接归档 A | 真实 thread/archive 接受，独立 loaded 列表确认卸载；随后读取设置被前置 loaded 检查拒绝 | 已卸载对象没有被读取入口主动恢复 |
| 检查与读取之间归档 B | 在真实 thread/loaded/list 已返回 B 后，暂缓将结果交回调用者；另一连接真实归档 B，独立确认卸载，再继续产品读取 | thread/resume 被原生明确拒绝，提示会话已归档，必须显式 unarchive；没有自动取消归档或重试 |
| 读取后的独立核对 | 独立连接再次确认 A／B 均未加载；各只有原启动 turn，均 completed，两个自有终端均已消失 | 未观察到存档恢复副作用或重复模型输入 |

这次验证确认：归档可以卸载仍有订阅的会话，但 0.169.0 拒绝直接 resume 已归档对象。此前离线对端“卸载后接受 resume 并重新加载”的模型不能代表这条真实归档路径。现有实现无需为已测路径修改控制逻辑；请求途中被原生拒绝仍按现有错误处理结束，不能报告设置确认。

## 失败与收尾

首轮在关闭前的进程身份检查停止：脚本把同一启动时间的 tuple／JSON list 判为不同。独立 SDK 读取核对两个原进程完全一致后，统一比较表示并复用原两个会话继续。首次失败、准确对象与操作记录均保留，没有重新启动会话、重发启动输入或重复归档。

所有自有终端、准确订阅均已清理；独立核验两个原生会话未加载，历史存档保留。配置、凭据、Codex 全局设置和本项目启动项摘要保持，日常运行制品未改动。新增离线归档拒绝用例核对错误传播、一次 resume 上限及不发 unarchive／start／settings update；连同双版本读取途中卸载拒绝用例，完整 934 项与编译／依赖／文档／diff 通过。

临时文件按清单清理了 31 个不再运行、可由保留的 wheel／sdist／lock／manifest 重建的 venv，以及一个由 package-lock 重建的渲染 node_modules，共释放约 1999.9 MiB。所有精确制品、锁、原始原生证据、数据库／日志／备份、5 份本人复制原件及本次验证环境保留；正式运行目录保持。

后续原生升级或新增卸载路径需重新核对该行为。未测试的强制卸载方式不沿用本结论；本记录不授予桥接自动 unarchive、恢复 notLoaded 存档或重放未知请求的能力。
