## 1．目标、交付范围与完成定义

在保持现有功能、原生身份安全及持久化语义的前提下，解决以下问题：

1. 长结果处理占用唯一原生事件消费者，使审批／追问延迟，并可能被无用增量通知挤满队列。
2. 每个候选端点复验再次扫描全部终端，导致发现成本随端点数量平方增长。
3. 历史回执增长后，阻塞分段查询反复扫描历史；相关任务查询索引不匹配，发送器持续空闲轮询。
4. Markdown 多阶段重复完整解析，增加大结果的 CPU 和内存开销。

本 Goal 交付**经验证的开发实现、可重复性能对照、回归证据、迁移工具和生产切换操作卡**。生产账本迁移、重启日常桥接和实际发布是独立交接步骤，不把开发完成描述为生产已生效；本 Goal 不替代 W08 自然上下文失效／恢复，不恢复 MD01 Mac 完整要求或 IMG01 同消息图文范围。

完成条件：G00 至 G07、全部必要 T／A 项通过，正式交付文档同步，原生 Goal 实际标记 complete。真实自动冒烟若被权限或缺少可安全使用的专用会话阻塞，保留未验证状态，不用模拟替代通过，也不越权启动生产切换。仅生产切换未执行不阻塞本 Goal 的开发交付，但必须明确标注“未部署／未迁移”。

## 3．修改边界与既定决策

### 3.1 允许修改的范围

- 原生通知与结果调度：`src/wx_clawbot/agents/rpc.py`、`execution.py`、`runtime_lifecycle.py`；只按需要触及 `interactions.py`、`subscriptions.py`、`controller.py` 的生命周期衔接。

- 账本查询、唤醒与显式迁移：`runtime_state.py`、`channels/state.py`、`schema.py`、`delivery.py`；只有 CLI 迁移入口确需变化时修改 `cli.py`／`operations.py`。
- 渲染：`output.py`；保持公共调用接口和既有冻结 payload 语义。
- 直接相关测试、合成 fixture、性能测量入口和第 10 节列出的交付文档。新文件先说明职责，避免无行为的框架层；优先使用标准库与已有依赖，不增加 Redis、后台服务或新核心依赖。

### 3.2 必须保持的行为

- 派发前仍复验 terminal ID、PID／进程启动代次／TTY、当前 footer thread、cwd、native runtime／session／thread；不可用时拒绝，不用长期缓存绕过。
- `/focus` 与 `/attach` 独立，原生队列、审批和追问仍绑定准确 thread／turn／request，原生运行时裁决交互赢家。
- 任务提交意图、client 身份、原生队列容量、FIFO、取消／中断及接收顺序保持。历史 unknown 不自动执行，网络 unknown 不自动重发。
- 终态和全部 final 回执仍在同一事务提交；渲染在事务外；FULL 同步、单消费者和状态单工作线程保持。
- 同任务 final 的先后阻塞、控制回执优先级、一次性发送意图和冻结正文／摘要保持；既有 accepted／unknown／rejected 不被重新渲染。
- Markdown 输入／输出语义、空白、代码／URL／路径字面值、前缀与每段上界保持。不得以截短结果、静默降级或改变兼容策略换性能。

- 本轮施工不操作微信 UI，不要求本人截图、复制代码或重复查看已验收样例；不把额外微信发送作为必要验收。以前测试批次授权均不能复用。

## 6．性能测量规则与量化验收

### 6.1 公平且可复现的测量

- 同一电脑、Python／精确依赖、固定合成内容，原版与候选使用不同进程／不同隔离账本，按 baseline／candidate 交替执行；不在跑满负载时测另一版本。
- 每个时间用例预热 1 次。普通渲染与 SQL 至少 15 个样本，最大容量至少 5 个样本，报告中位数、p95、最大值和所有原始样本；p95 用 nearest-rank，不能用一次最快成绩代替。
- profile 单独运行，不计入性能对比；CPU／RSS 只记录本次进程及其拥有的测试子进程，并说明字节单位。区分本地控制“收到规范化请求至准确交互／控制回执提交”与微信公网／手机显示耗时。
- 所有压测有超时、资源上限和失败报告，异常路径停止并回收自有工作。先跑确定性断言，再跑时间门槛；环境繁忙导致失败时记录原因，在同等条件下原版／候选成对复验一次，持续不达标则保持未完成，不自行放宽门槛。
