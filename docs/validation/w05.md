## 命令、路由及启动登记

已实现固定命令语法与别名、不可变列表快照、接收时冻结目标、路径真实解析及越界拒绝、异步路由 revision 校验。focus 与独立 observer 分开保存，列表刷新退出输入聚焦，detach 不清空执行目标。该部分是组件行为；微信主循环和原生订阅接线尚须完成验证。

可见启动使用私有 launch_id 登记和固定 Python 入口。iTerm2 command 只传固定入口、私有登记路径和 ID；项目目录、标题从登记读取，子进程经 exec argv 启动原生 Codex。首次调用前保存 starting；取消、丢回执或未知结果不再次调用宿主。只获得终端回执时为 handshaking，不能 ready。

两个独立临时项目实际启动到同一个任务自有窗口的两个标签；第二条路径包含空格、引号和 `$()`。SDK 端点、启动子进程 PID／微秒级启动身份、屏幕握手标记和同运行时 native thread 一一匹配，两条启动 turn 均完成。相同 launch_id 重试前后实际标签数量均为 2。未使用模型或一般配置覆盖参数执行这两条启动。

SDK 入口已核对本机固定 2.30 版本及[官方 Window 文档](https://iterm2.com/python-api/window.html)。公开文档说明创建窗口／标签的行为，实际会话关联以上述现场核验为准。

## 同进程内切换会话的反例

在任务专用标签完成原生 `/new` 当前工作区选择，并提交只读标记后，实际出现新的 native thread。旧 thread 仍为 idle，canAcceptDirectInput 仍为 true，进程身份不变。这证明单靠 PID、sessionId 和已加载状态不足以确认桌面当前会话。

实验早期的工作区弹窗和未提交草稿均未当作会话切换成功；核对专用终端画面并按已验证的输入稳定顺序提交后，才取得两个不同 thread 的证据。后续显式测试输入使用 suppress_broadcast=True；核对时广播域为空。测试只操作任务所属标签。

## 被动显示身份的修复验证

[官方开发者命令](https://learn.chatgpt.com/docs/developer-commands) 提供 Session ID 状态栏项。另建一个任务自有测试标签，只通过进程参数临时设置 session-id，显式接入原 daemon，使用已信任的项目根目录完成只读标记；该实验没有写全局配置。

真实观察：页脚 ID 与原生 thread 完全相同；完成 `/new` 和新只读标记后，页脚改为新 thread ID、排除旧 ID，进程仍相同，旧 thread 仍加载且可输入。新的绑定复验真实拒绝旧绑定、接受新绑定。试验前后全局配置摘要相同。

实现仅从 TUI 保留的页脚行读取 UUIDv7，不扫描历史或输入框猜测。显示缺失、截断、多个 ID 或身份不一致时拒绝派发。发现目录先核对进程 cwd 是否属于注册项目，再读取该终端页脚及项目限定的原生元数据；未注册项目不会触发页脚或原生历史读取。
