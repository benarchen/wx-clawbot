### 语法、目标与作用域

1. 采用确定性解析；修改为 `/model set <准确模型> [推理强度]`，模型和可选等级各一个，禁多余参数和换行混合输入。旧模型直写／reasoning flag、`/model --speed`、任意 `/codex <字符串>`、终端按键及 Shell 解释不支持。未知命令不能降级成普通任务。
2. `/model`、`/fast`、`/codex status` 以微信输入目标为准，不以观察目标、当前目录、唯一终端或桌面当前画面代替。`/model list` 只读当前运行时目录，`/help` 无原生依赖；无目标时前两者不能借查询偷偷选择会话。
3. 接收时冻结目标，派发设置前重验目标修订、注册资格、原生代次、thread／native session、cwd／provider、loaded 及订阅资格。接收后切换、unfocus、项目 remove、卸载或重连使旧请求失效时拒绝，不改投新选中对象。查询失败不释放已有选择／观察，查询不触发任务对账或启动宿主。
4. 写操作只影响该准确原生 thread 的后续任务；不改用户全局默认模型、配置文件、权限、认证、Skills、插件或其他 thread，不修改已运行 turn 的模型，不迁移队列、取消任务或重放 unknown。桥接自身不另存一套覆盖原生的模型／档位默认值。
5. 所选模型、显式或目录默认的推理及当前服务档位必须兼容；模型命令只发送约定的 model／effort，Fast 只发送 serviceTier，其他字段保持。省略推理明确表示采用模型目录默认，不是保持当前值；不清空档位／换 provider，不自动选替代组合。联合请求不宣称原子，部分变化或证据不足保留未知，不回滚。
6. Fast 支持取决于目录及实际模型／账号环境；目录、设置接收和实际推理访问是三种证据。列表使用模型准确 ID，不将界面序号当持久模型标识，不用第三方静态模型清单替代运行时结果。

### 生效、并发、重复与未知

- 写前核验没有原生活动 turn、完整队列项、桥接已接收／预留／正在派发任务、未结审批／追问及原仓库占用。只证明空队列或窗口关闭都不等于空闲。查询命令允许在忙碌时执行，但不得顺便改变设置或任务。
- 将设置操作与现有接收／派发、选择、移除和原生代次变更放进同一可核验协调范围，设置处理中建立项目／thread 引用，阻止 remove 穿透；不持 SQLite 事务或文件锁跨网络 await。原生控制不伪造 `t-` Agent 任务、不占用第二个微信消费者。
- 不能用桥接锁宣称与桌面输入实现了原生原子互斥。G02 核验结果表明没有条件写保护，原生允许 busy／queued 更新；按本人 2026-11-10 确认的边界，产品只拒绝可观察的已知忙碌并披露检查后桌面竞争。桌面开始任务或修改设置发生在窗口内时，以准确原生回读／事件为证据，报告冲突或已确认的当前设置及范围，不承诺已有队列固定入队时设置，不把旧值覆盖回去或自动重试。
- 必须在 G02 固定当前设置快照的无副作用来源、设置写入回执与匹配设置事件／回读的关联方式。只收到 `{}` 或请求 ACK 不返回“已生效”；事件早于响应、乱序、重复、来自其他 thread、同 thread 桌面并发修改都需处理。不能把任意后到的同值通知认作本次写入的唯一证明。
- 复用现有本人绑定、消息去重与冻结回执。写意图须在发送原生请求前持久化，记录准确对象／请求指纹和状态；优先现有可审计入口，确需补充时只增加最小、有界、0700／0600 的私有控制记录，G02 明确格式、锁、保留和容量。控制记录只作去重与证据，不是原生设置权威，也不能混写项目注册配置或冒充 Agent 任务。计划不默认授权数据库迁移；如确有 schema 变化必要，先提交具体迁移／备份／恢复方案并取得对应授权。
- 同一微信消息重复投递或回执投递重试不能再次调用设置；新的显式同值命令在可靠原生读值后无变更返回。RPC ID 只作传输关联，不当作服务端幂等键。意图落盘后崩溃、发送后超时或断连一律保留未确认状态，不自动重放／回滚；恢复先只读核对，不能确认则明确提示，待本人查看 `/model`、`/fast` 或 `/codex status` 后再明确下达新操作。
- 状态回执携带准确稳定会话编号、实际模型／推理／档位及必要来源时点。已选择与已确认实际执行分别描述；后续任务失败不能反过来把先前目录结果伪造成访问验证。模型不支持图像时沿用原有图片校验，不自动换模型／去图／重发。

### 用量与帮助

`/codex status` 优先提供当前设置、原生运行状态和完整队列数量；用量只展示匹配 thread／turn 的原生事件或受支持只读接口能够证明的字段，并区分本轮、累计、上下文窗口、账号级限额及其时间。用量缺失或无法证明分母／有效上限时显示未提供，不从模型标称窗口或本地消息长度估算百分比，不把账号用量当成本会话。首批不扩大为计费报表、扣费承诺、账号限额重置、消费额度或账号操作。

### 真实原生与手机操作卡的准备要求

- 先自主完成设计、离线实现／失败路径与冻结候选，再提出具体配合。默认一个专用 iTerm2 窗口、至多两个命名标签，使用两个临时项目；保留各自 boot／进程／准确 native 对象身份，清理仅限确认归属且任务与控制意图终态已核对的会话。
- 开始前列出测试模型、可用推理等级／Fast 档位、设置切换次数、短标记任务数量与可用账号条件，不拿真实业务对话做验证。正向切换至少覆盖实际可选的两个模型／两个推理值及 Fast 开／关；每项条件不足时记录待验，不用伪造目录或模拟响应填补真实通过。确无适用 Fast 环境时先列出目录证据和未覆盖范围，由本人确认后续验收安排，不自定免验。
- 先核 A／B 初始设置及全局配置保护摘要，真实读／写／后续采用证据分开；不用模型自述“我使用某模型”代替原生 turn／设置字段。TUI 显示和 backend 值都要观察，必要的人工截图／状态查询写入操作卡，不以终端标题或页脚为身份来源。
- 本人手机操作卡逐条列命令、预期回执、错误与忙碌窗口、原目标变化、切换／停服时长和恢复步骤。微信由本人操作，不自动登录、点击或补发测试消息。当前只授权制单，真实资源与消息仍需届时针对具体范围授权。
- 日常制品切换不在本 Goal 自动授权内；若手机验收必须临时候选运行，先准备新独立版本目录、原配置／账本备份、空闲与单消费者检查、旧数据保护及恢复卡。私有控制记录随新写入保留，不恢复旧库掩盖未知；本人已授权范围内连续完成，关键风险变化才重新澄清。
