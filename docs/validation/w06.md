## 实测环境与数据升级

Python 3.14.5、iTerm2 SDK 2.30、Codex daemon 0.164.0；原生任务均在两个专用临时项目的既有终端执行。未更改模型、认证、Skills、插件或全局配置。

本人明确授权真实运行库升级。2026-10-25 18:50，旧前台经准确进程身份核验后 SIGINT 并退出 130；持有消费者锁时验证独立 schema 1 备份，再事务升级至 2。原五表全部旧列按行序摘要一致，保留 27 条入站、9 个已完成任务、50 条已受理回执；完整性、私密权限和全局配置基线检查通过。新前台恢复 ready，另用官方 SDK 只读复验七个专用终端，没有发送终端输入。

## 真实原生进程崩溃

入口为 [w06_recovery.py](../../tests/integration/w06_recovery.py)，显式参数限定两个临时项目、两个准确 native thread 和私有输出目录。每个检查点先持久化独立意图，工作子进程在指定位置真实 `os._exit(86)`；既有检查点拒绝重新提交，恢复入口只有只读原生核对。微信入站及发送为替身，未使用真实微信传输。

| 崩溃位置 | 原生实际执行次数 | 恢复提交次数 | 恢复结果 |
| --- | ---: | ---: | --- |
| 调用 queue/add 前 | 0 | 0 | unknown，缺少记录不作未执行重投 |
| 提交帧已发、尚未读回执 | 1 | 0 | completed，准确 client／thread／turn |
| 原生回执已读、本地尚未记队列身份 | 1 | 0 | completed，原结果恢复 |
| 终态与 Outbox 事务中途 | 1 | 0 | 未提交事务回滚，原结果恢复 |
| 最终 Outbox 已提交 | 1 | 0 | completed，发送已有结果 |

四条已执行任务的原生结果均包含各自独立标记；准确原端点复验、全局配置基线均通过。恢复最终结果各发送一次的断言使用模拟发送器，不能据此声称手机收到。

真实测试发现 SDK 应用单例在手动关闭连接后仍引用旧连接；已按锁定 SDK 的公开连接字段清理所属缓存，并测试不影响另一个活动连接。首次提交前检查点只做了原记录恢复，没有重投。分批测试还发现汇总文件名冲突；各检查点的核验记录已先完成，修复后保留旧汇总并只读整理五份证据，未重做原生任务。

## 真实本人微信 HTTP 发送崩溃

入口为 [w06_delivery.py](../../tests/integration/w06_delivery.py)。只加载本项目已确认的本人凭据，私有测试账本使用同一本人回复上下文；不轮询、不推进主游标，不读取其他项目数据，不创建 Agent 任务。三处均真实结束发送工作子进程，再重新打开本地账本。

| 崩溃位置 | 实际 HTTP 发送次数 | 恢复后的投递状态 | Agent 新任务 |
| --- | ---: | --- | ---: |
| sending 意图提交、HTTP 调用前 | 0 | unknown，不自动重发 | 0 |
| 服务端已确认、本地尚未登记发送结果 | 1 | unknown，不冒充失败或重发 | 0 |

主运行库任务映射在测试前后完全一致。两次实际发送仅面向本人，各使用独立测试标记；本人明确确认“两条各收到一次”。手机确认单独留证，不将本地 unknown 改写成 accepted。

## 输出与离线边界

281 项离线测试通过；覆盖路由落库失败、交互竞争／过期、原生未知关联、Git worktree、十条准入、桌面任务控制与独立观察、分段顺序、发送尝试和保留期回滚。新增测试确认出站渲染不改变任务输入，3000 行代码分段保留各行且每段有完整显示围栏，超长交互不提供截断审批，异常超长围栏有明确说明并保留原文片段。普通测试不访问真实微信或用户终端。

本人截图确认普通 LF／CRLF 合并、双 LF／U+2028／U+2029 分行。另一次真实单消息对照显示说明文字硬分行、两行 Python 代码按代码块显示并有复制按钮；原始代码字段及本地断言逐字保持，未操作复制按钮或声称检查了剪贴板。渲染器采用经验证的说明硬分隔与代码围栏，未新增协议字段；具体归一化发生于服务端还是客户端仍未独立定位。

超长单行压力用例暴露新渲染正则的平方级路径，已先检查长度并限制渲染输入，再执行代码识别；停止的仅是卡住的离线测试进程。修复后本机对 600011 字符输入运行 50 次，保留尾部与独立错误，输出 480020 字符；渲染 p95 为 0.477 毫秒、最大 5.195 毫秒。口径为函数调用到返回，不含 SQLite、原生、网络和模型，不能代替 V08 的控制延迟与资源验收。

## V08 真实负载与本地控制

入口为 [w06_load.py](../../tests/integration/w06_load.py) 和[独占轮询故障](../../tests/integration/w06_channel.py)。两份原临时项目各初始化独立 Git 元数据，原 AGENTS.md 摘要及业务文件列表不变；两个准确原生会话分别执行只读 sleep 计时任务，随后各装入十条原生队列。第十一条被拒绝；准确取消一条后补入新请求，最终二十条按各自 FIFO 形成独立 turn，每个 client 恰好出现一次，取消项未执行。

| 测量对象 | 实际结果 | 口径 |
| --- | --- | --- |
| `/status` 本地处理 | 1893 次，p95 5.453 毫秒，最大 12.542 毫秒 | 规范化接收到 inbox 与控制 Outbox 落库，含 SQLite；不含模型、公网和发送 |
| 排队取消 | 63.952 毫秒，原生确认删除 | 同一接收与回执边界，包含本机宿主与原生查询；单次样本，不冒充停止 p95 |
| 原生事件 | 5398 条，其中文本 delta 4922 条 | 单一事件消费者，非字符级微信推送 |
| 事件队列 | 高水位 31，上限 256 | 实际入队后记录高水位 |
| 测量时段 | 208.750 秒 | 含计时门、队列执行、真实轮询故障与恢复 |
| Python 分配 | 结束并清理后 571073 字节，峰值 1190811 字节 | tracemalloc，不等同整个进程 RSS |
| 进程峰值 RSS | 53821440 字节，约 51.328 MiB | macOS getrusage；另约每五秒采样本进程 RSS，完整数据见 JSON |
| 原生长结果 | 12264 字符，分两段 | 原生真实生成并核对，批量负载发送器为替身；另用本人真实通道发送两段并获本人确认顺序正确 |

负载期间独占本人通道，真实关闭已发起长轮询的 TLS socket，观察到 TransportError、游标不变；下一次真实响应接受成功，没有新本人消息被执行。其他服务及工作终端未操作。当前时段数据说明本次负载有界，不构成长驻内存泄漏或所有机器延迟的保证。

首次负载只因验收器未识别合法 `zsh -c` 包装而在计时门停止，未提交二十条任务；实际命令均为唯一 sleep。核对原生记录确认旧门任务完成后，以独立新来源执行负载；仅允许已核实的 `-c`／`-lc` 内部精确 sleep，注入与其他命令仍拒绝。未改写失败记录。

## 真实结果重试与新增边界

本人明确授权唯一专用回执的一次可能重复送达测试。先只读准备，再用 [w06_retry.py](../../tests/integration/w06_retry.py) 对临时项目中一个已完成的真实微信任务发送既有结果：第一次真实受理后工作进程退出，本地恢复为 unknown；显式准备一次重试，第二次受理为 accepted。两个尝试分别保留 unknown／accepted，实际 HTTP 两次；准确原生 client／thread／turn 在前后均只有一次执行，主任务全行快照一致。没有重试其他 unknown，没有新建或执行 Agent 任务。

另用真实活动桌面会话验证缓存遗漏边界：准入前重新发现后识别同项目活动，新意图保持 received，native queue/add 为 0；撤销等待后，桌面结束时新来源正常完成。初版测试器在发起原生任务前的异步生成器写法已修正，核对零入站／零任务／无 turn 登记后才继续同一未执行记录。该修正是准入前只读发现，不改变已测 `/status` 路径，未为此重跑整套负载。

桌面主动任务以 external 登记，无伪造入站；通过控制器停止后，真实原生 turn 确认为 interrupted，原终端保留。补充确定性竞争用例确认：停止意图在 RPC 前落库，完成先于回执或回执丢失时不覆盖原生终态；排队取消转运行时重新读取准确 turn。
