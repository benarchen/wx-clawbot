# wx-clawbot 施工清单

本文保存设计与验收要求；实际进度与验证状态以仓库 ROADMAP.md 为准。

输入：[产品设计](../docs/product-design.md) 、[架构设计](../docs/architecture-design.md) 、[技术选型](../docs/technical-decisions.md) 、[开发契约与 V00 至 V08](../docs/development-contracts.md) 。

## 1. 目标与范围

让本人微信能在 guixu、wx-clawbot 等已注册项目之间切换，操作 iTerm2 中已有的 Codex 会话，并创建新的可见会话。原终端持续可用，任务可排队，审批和追问双端共享且先答生效，结果可核对，断连不重复执行。

本项目与 openclaw-local 完全独立；禁止读取、参考、复用或修改其代码、配置、凭据和服务，不安排关联迁移或退役。

项目修改位置是 `<project-root>/`，不是 guixu。guixu 仅在最终按明确任务授权进行验收，知识目录、脚本和项目规则不为桥接项目改造。

## 3. W00：建立可开发的工程

目标：先固定项目边界，再实现代码。

- 在空目录先创建 AGENTS.md：项目定位、结构职责、文档导航、全局规则继承、配置隔离、验证入口及修改边界。
- 将本轮设计文档迁入 docs，改为仓库相对链接；README 仅说明设计／原型真实状态，ROADMAP 登记任务和阻塞。
- 创建 pyproject.toml、最小 Python 包和 unittest 入口；不添加无行为的框架层。
- .gitignore 排除 .venv、缓存、构建产物、.tmp、真实配置、私有运行数据、系统和编辑器文件；允许脱敏模板。
- 从工程开始使用 Git；main 保存已验收稳定基线，dev 用于日常开发与阶段提交。

验证：目录与文档链接有效，测试入口可运行；配置模板不含身份或凭据。Git 初始化可纳入明确的开发任务，本次已授权阶段提交、公开空仓库创建、配置 SSH 远端；完整首版验收后才合并和推送 main、dev，不创建 tag 或 Release。

## 4. W01：冻结依赖和协议输入

目标：使后续原型可复现，不依赖浮动 main 或未测试的最新包。

- 在项目 .venv 安装并测试 iterm2 候选版本，核对 Python 3.14 和 iTerm2 3.7.6 的兼容性。
- 补齐核心依赖近期发布、维护者活动与 issue 响应检查；记录未解决问题，锁定直接与传递依赖版本、哈希和许可证。
- 固定 Codex CLI 基线；生成稳定及必要的实验 schema，将实际使用的最小脱敏 fixture 纳入契约测试。
- 固定腾讯参考源码 commit、版本与关键文件哈希，建立请求字段对照；不 vendor 整个 OpenClaw 或 weclaw。
- doctor 只读检查版本、路径、依赖和权限；未启用 iTerm2 API 时给出具体启用要求。

验证：新建 .venv 可按锁文件重建；依赖导入成功；schema fixture 可校验预期字段；不写全局 Python 或 Codex 配置。启用 iTerm2 API 属于独立系统设置步骤，不在依赖安装中悄悄完成。

## 5. W02：证明微信能控制原会话的基础

目标：在接微信前，通过本地测试驱动验证同一终端、同一 thread、连续上下文。

- 实现 ItermHost 的发现和端点核验，区分普通 Shell、Codex、已退出端点。
- 查明真实运行时连接地址与归属；实现 Codex proxy 的 JSON 消息连接、初始化和事件读取。
- 建立 terminal、process、runtime、thread 的可靠关联；覆盖同目录多个会话和身份重用。
- 完成 V01、V02：终端先发、桥接再发、终端继续，核对同一 thread 的三轮记录。
- 对独立运行时、协议不匹配、无事件权限提供明确错误；不自动重启已有 Codex。

交付：最小原型和脱敏验证记录。验收失败则在此解决接入问题，不先铺开命令和部署系统。允许修改 agents、hosts、对应 tests 与文档；不得调整用户正在工作的终端或真实业务文件来凑测试。

## 6. W03：证明双端交互与队列成立

目标：完成最重要的并发行为，关闭 D04、D05 的接口风险。

- 把原生请求 ID、连接和运行代次映射成公开请求 ID；实现类型校验与完成状态同步。
- 完成 V03 的两端先答、冲突竞争、追问、失效与重连场景；记录实际裁决点。
- 实现原生队列关联，验证 client_submission_id、queue ID 和 turn ID 的关系。
- 完成 V04：两端忙碌提交、排队取消、运行中断、回执丢失、无重复任务。
- 控制命令走独立处理路径；不受普通任务队列阻塞。

验收：本地测试驱动也须使用真正的原生交互，不以测试替身通过平台能力关卡。如果原生连接不支持共享审批，记录具体失败请求和版本，先研究可行接口；任何改变双端体验的替代方案须明确提出。

## 7. W04：接入微信文本

目标：形成独立于 Agent 的最小真实通信闭环。

- 按冻结源码逐字段实现登录、长轮询和发送；HTTP 与业务错误分开处理。
- 本地配置本人身份绑定，验证入站发送者与出站对象；保存凭据到私有运行目录。
- 明确实际消息去重身份、游标和 context_token 的更新规则，覆盖未知类型与异常响应。
- 长轮询与发送使用独立有界资源；重连退避，停止时有有限超时，不无限创建线程。
- 完成 V06 的本人通信闭环、去重、游标与断连恢复；扫码与发消息在明确安排的本人联调中执行。本人于 2026-10-25 同意自然过期上下文转入 W08 长时间真机验证，不阻塞 W04 阶段交付，不免除最终验收。

验收：真实手机收发成功且有脱敏证据；未知身份不能启动 Agent。旧服务如占用同一绑定，先安排明确的切换范围，不自行读取旧凭据或停止服务。

## 8. W05：完成多项目和会话操作

目标：命令行为与产品文档一致，目标选择始终可解释。

- 注册 guixu 与 wx-clawbot；fixture 阶段使用两个独立临时项目，覆盖 realpath、符号链接、无效目录。
- 实现 projects、cd、sessions／ss、send／s、focus／f、unfocus／uf、new、status、stop、approve、deny、answer、help。
- 列表使用稳定身份快照；任务接收时冻结路由；焦点切换不改变已有任务目标。
- 完成新会话启动握手与 V05，处理重复启动和启动中断。
- 验证项目规则读取及更新后的生效；不把 guixu 的知识库工作流硬编码进桥接层。
- 提交 attach／detach 的差异说明：独立控制行为、与 focus 重叠部分、所需接口；形成明确命令决策并同步产品文档，不静默删掉。

验收：P02 至 P06 对应场景通过；没有选定目标时不猜测；启动失败不会产生伪成功会话。attach 的处理结论必须在首版完整验收前关闭。

## 9. W06：可靠性、恢复与输出

目标：执行一次与可靠回执分开处理，恢复不扩大副作用。

- 实现 SQLite inbox、任务、路由、交互、Outbox 和游标的必要事务与约束。
- 提交意图先持久化，外部调用结果未知时进入 unknown；恢复先核对原生记录。
- 实现文本分段、优先级与进展合并；正文和日志有上限，最终错误不静默丢失。
- 中文排版只处理自然语言展示，代码、命令、路径和 URL 保持原义。
- 完成 V07 故障注入；记录执行恢复与发送恢复的不同结果。
- 完成 V08，报告实际测量口径和数据；未达目标先定位，不以模型耗时掩盖本机阻塞。

验收：P09 至 P11、P13 通过；发送重试不触发执行重试；超过队列上限、磁盘写入失败、超长输出和连接失效均可解释。初版数据库创建属于项目实现；未来迁移真实运行数据遵循单独授权边界。

## 10. W07：可用性与运维

- 提供前台运行、status、doctor 和受控退出入口，错误能定位到通道、宿主或 Agent。
- 使用 `~/Library/Application Support/wx-clawbot/` 保存私有运行数据，路径和权限可检查。
- 准备用户级 launchd 模板、启动／停止／卸载说明；先验证模板，不自动部署。
- 配置修改和停止服务不默认杀死用户 Codex；HOST01 将微信接收与依赖恢复分开，先允许静态命令及状态查询，原生新任务仍须等待依赖恢复和完整身份核验。
- README 写实际安装、使用、失败恢复及已支持命令；ROADMAP 写未通过项，避免把愿景当当前能力。

验收：可从新终端按说明启动前台服务；doctor 不泄露凭据；配置前后核验不包含输出敏感内容。常驻注册、微信迁移、旧服务退役另按明确部署范围执行。
