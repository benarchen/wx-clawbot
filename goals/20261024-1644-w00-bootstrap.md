# W00：工程与规范初始化

## 目标与预期行为

建立可开发、可验证且适合公开的独立仓库，完整迁移六份材料；实际实现只读配置诊断与测试入口，不宣称桥接功能可用。

## 背景、入口与依赖

用户已授权材料移动、Git 初始化、阶段提交及公开空仓库创建；仅完整首版验收后推送。先读全部六份输入材料，继承全局规范及项目 AGENTS.md。工作包定义见 [施工清单](implementation-plan.md)，进度只见 [ROADMAP](../ROADMAP.md)。

## 已确定决策与修改范围

Python／asyncio；iTerm2 与 Codex 原生接口；dev／main。允许修改本项目规范、迁入材料、工程与测试、配置模板、Git 元数据；核对迁移完整后移除六份桌面源材料。不得访问旧独立项目，不修改 Codex 全局配置或现有服务，不触碰用户终端，不推送未验收实现。

## 检查点

1. 核对现场、规范、材料和 Git 身份；项目规范先于实现目录建立。
2. 保存材料原始摘要，在目标无冲突时复制、校验一致，再申请必要文件系统权限移除源文件；公开版本修正链接、私人路径及过时约定。
3. 建立忽略规则、配置模板、包与只读 CLI 行为；真实运行测试发现和无效配置边界。
4. 检查链接与公开内容，建立 main 最小规范基线，再建 dev；核对 GitHub 归属后创建空公开仓库及 SSH 远端。

## 测试与关键失败路径

迁移前后 SHA-256 一致；链接解析无缺失；不存在嵌套仓库。配置测试覆盖未知字段、路径缺失、重复别名、越界路径；不输出凭据。unittest 发现数量必须大于零，编译检查与 diff 空白检查通过。GitHub 认证或网络失败明确记录，不擅自换账户或覆盖远端。

## 验收标准

材料内容迁移完整，规范冲突已消除；工程诊断与测试入口实际可运行；公开文件无真实凭据或私人路径；main／dev 本地基线可核对；GitHub 创建如受外部门禁阻塞，保留独立待办，不能假称同步。

## 交付结果

六份原文逐份 SHA-256 一致后完成迁移并移除源文件，公开版本修正链接及冲突内容。6 项真实单元测试、编译、doctor 和文档链接检查通过。公开空仓库已创建，本地 main／dev 基线建立；未推送代码。材料原文摘要仅留在忽略的任务临时目录，公开文档不依赖它。
