# 微信命令与选择契约

本文维护当前开发树的微信命令行为，应用基线为 0.1.12；2026-11-08 本人要求 `/sessions` 改为纯查询，开发验证与部署状态分别见 ROADMAP。独立观察于 2026-10-25 本人确认，独立选择和无读屏身份于后续 TGT01／TGT02 确认并交付。路径保留 proposal 字样仅为链接兼容，不表示这些命令仍为未实施提案。

## 命令总表

PRJ01 的 project 子命令已完成离线、专用原生及本人手机闭环验收，随 0.1.11 公开发布并本机加载；旧 0.1.10 不支持新子命令。参数、即时生效与取消注册保护以[项目管理契约](project-management.md)为准，验收状态见 ROADMAP，不能把候选通过当已部署。

NCM01 首批原生命令见[专题](native-controls.md)。`/model`／`/fast` 查询、显式设置、`/codex status` 和 help 新分组在 0.169.0 的原生及手机功能验收已过，源码纳入 0.1.12，同一正式制品已本机加载；Git 与部署证据分别见 ROADMAP。写入不得只凭 ACK 报成功，模型修改统一 `/model set <模型名称> [推理强度]`，省略使用所选模型当次目录默认、缺失则要求明确指定；联合发送并同时确认两值，不承诺原子性。原 `/status` 语义保持，未支持命令不转普通输入。

输出采用简短标题、独立段落和中文状态，避免微信折叠单换行。默认 `/codex status` 保留模型、思考等级、Fast、忙碌／非空队列和账号额度，隐藏 token 诊断明细及完整会话编号；模型列表每项分组且不重复名称。展示用短会话编号不作为命令参数；`/sessions` 仍显示完整会话 ID，任务、审批及追问的操作编号保持完整。具体约定见[默认展示](native-controls.md#默认展示约定)。

| 命令／别名 | 前置与成功行为 | 失败／边界 |
| --- | --- | --- |
| `/help` | 列出全部命令、参数、别名和简短用途；每条说明尽量不超过 20 字，确实无法准确表达时才适当放宽 | 保留必要共用提示，详细规则由本文维护；不执行自然语言或拉起宿主 |
| `/project`、`/project list`（0.1.11 起） | 注册项目及目录可访问状态 | 纯查询，不初始化／重扫、不选会话 |
| `/project add <目录名> [--alias <别名>]`（0.1.11 起） | 注册总目录下已有直接子目录，持久化并即时生效 | 不创建目录／会话，不切换目标，不接受外跳路径或冲突替换 |
| `/project remove <别名>`（0.1.11 起） | 解除目录关联，保留文件／原生对象／历史／回执 | 输入／观察／任务／占用或未结意图阻塞；无 force，旧列表失效 |
| `/project check [--request <请求 ID>]`（0.1.11 起） | 只读注册诊断，核对最近请求 | 不等于 doctor／工程测试；无记录不等于从未执行 |
| `/projects` | 注册项目及状态；0.1.11 起作为 list 兼容入口 | 不扫描所有磁盘仓库 |
| `/cd <项目或路径>` | 合法 realpath，选择相同项目／cwd 的可核验受管对话；没有时可见创建，成功后 managed 输入目标 | 相对路径基于当前目录；越界或不可访问不切换；多个受管候选不能猜 |
| `/sessions [关键词]`、`/ss` | 纯查询：刷新／筛选项目别名、目录、标题，显示范围与稳定桥接编号；保留输入目标和观察订阅 | 不启动 iTerm2、不恢复选择、不订阅／退订或触发任务对账；失败保留原列表且不延长有效期；不递归子目录 |
| `/send <序号> <指令>`、`/s` | 本次快照准确目标单次派发 | 不改变持久焦点，不另建替代会话 |
| `/focus <序号>`、`/f` | 准确原生对象、输入／观察能力和订阅确认后选择后续普通消息目标 | 失效／不支持拒绝，不跟随当前窗口 |
| `/unfocus`、`/uf` | 清除输入目标，原任务继续 | 不恢复更早焦点，不取消观察 |
| `/attach <序号>`、`/a` | 独立订阅后续桌面任务；真实订阅确认后持久化 | 不改变输入目标，不复制历史，不取得排他控制权 |
| `/detach`、`/ua` | 只取消独立观察，保留执行目标与已接收任务 | 不关闭终端，不中止任务 |
| `/new [标题]` | 已有合法当前目录，自有可见启动及唯一原生完成握手，随后 managed 选中 | 标题最多 128 字符；窗口回执不等于 ready；未知创建不重复 |
| `/status [任务ID]` | 不带 ID 显示目标／观察、依赖、未结束任务、待处理交互和投递汇总；带 ID 显示任务状态、占用及相关异步补充问题 | 不重发完整结果；离线值标最后记录，不冒充刚核验 |
| `/stop [任务ID]` | 省略只在当前目标有唯一有效占用候选时操作；准确 ID 可指定任务 | 多候选须 ID；released unknown 不是裸停止候选；撤销／移除／中断分别确认 |
| `/approve <请求ID>`、`/deny <请求ID>` | 准确本人同步命令请求，一次性原生决定 | 过期／已处理／错代次拒绝，不暗增永久许可 |
| `/answer <请求ID> <答案>` | 同步 r- 请求或异步 q- 请求分流，按各自格式和期限核对 | 不把裸选项猜成回答，不在旧 turn 后自动新建任务 |

项目列表的紧凑展示约定见[项目管理](project-management.md#命令与产品边界)：项目名加粗、总目录仅显示一次，正常项省略状态，路径不一致或异常时补充完整路径；check 保留详细诊断。该展示改动的实际发布状态以 ROADMAP 为准。

所有输入先做固定语法及长度校验；未知 slash 命令返回帮助，不执行 Shell。稳定桥接 s- 编号只帮助识别，当前选择语法使用本次正整数序号；不能将 s- 编号当 native thread 交给 codex queue。

## 快照、目标与交互格式

数字序号仅在最近一次成功列表快照内有效，默认 600 秒；刷新／连接换代后需重新取得。查询仅替换内存列表，不改变路由 revision 或持久化选择；空列表、关键词不匹配或原目标未列出也不清除输入目标。查询期间普通消息仍冻结原目标，派发独立复验；列表中的存在与否不代替派发核验。原生未就绪或查询失败时明确提示，本次未刷新，旧列表按原期限处理。接收时冻结完整目标与 route revision，异步执行不得重新按新列表解释同一序号。选择提交先获得原生订阅确认再持久化；失败保留可恢复的原状态，不能报成功。`/unfocus` 清除输入目标并释放其 route 订阅；观察和任务订阅保留，但没有其他订阅的原生对象可能随后卸载，不等于删除聊天记录。

同步多题采用原生题目 ID 到回答数组，例如 `{"choice":["PHONE_ALPHA"]}`；异步多题必须完整 q 键到字符串，例如 `{"q1":"答案一","q2":"答案二"}`。以通知里的准确 ID 作答；同步十分钟仅限制微信入口，不自动裁决原生请求，异步 600 秒内任务可能继续。细则见[开发契约](development-contracts.md)和[异步专题](async-questions.md)。

## 独立观察订阅

`focus` 已有明确职责：选择后续普通文本的执行目标。若把 attach 也定义为选择目标，它与 focus 没有独立行为；排他接管、强停桌面、后台迁移均与已确认需求不符。

独立职责为观察订阅：

| 命令 | 可执行契约 |
| --- | --- |
| `/focus <序号>` | 选择普通消息路由目标，任务回执及必要交互继续关联其原任务；不自动订阅全部桌面主动任务的输出 |
| `/attach <序号>` | 订阅该原生会话中桌面主动发起任务的后续进展、结果及交互；不改变普通文本的 focus，不重放历史结果，不创建或迁移 thread |
| `/detach` | 取消当前观察订阅；不清空 focus、不取消任务、不关闭终端；桥接已接收任务的结果与必要审批继续按原关联投递 |

首版每个微信绑定最多一个独立观察订阅，重复 attach 同一目标幂等；attach 另一目标时明确回显替换的订阅。绑定失效或不支持原生事件订阅时返回错误并保留原状态；未收到正式订阅确认不得回复成功。

示例：focus B 项目，attach A 会话；普通文本发往 B，同时收到 A 桌面任务的进展。detach 后普通文本仍发往 B。状态分别显示“执行目标”和“观察订阅”，避免把观察当作控制权迁移。

曾评估把 attach／detach 作为 focus／unfocus 的兼容别名；本人已选择独立观察订阅，因此不采用该替代方案，detach 不清除普通消息目标。

原生事件订阅和两端交互的历史验证见 W02／W03，完整命令与后续身份演进证据见[追溯矩阵](requirements-traceability.md)；不把旧确认提案当作当时已完成实现。

## HOST01：宿主生命周期契约

HOST01 原验收允许合法 `/sessions`、`/cd`、`/new` 按需启动宿主；2026-11-08 按本人要求收窄为合法 `/cd`、`/new` 在满足参数和目录前置条件后可按需拉起未运行的 iTerm2。`/sessions`、帮助、项目列表、状态及普通消息不触发拉起。历史 HOST01 记录保留当时行为，当前验收与部署状态见 ROADMAP。应用主动退出后后台只等待重新运行，不反复打开应用或弹授权。

宿主连接断开不能阻塞微信通道；会话命令及时给出进展及有界结果。重新启动应用后自动重连、失效旧数字列表并完整核验准确原生身份；既有对话不要求当前终端存活或显示。只有准确原会话可恢复旧选择，不能按标题或目录猜测；原会话消失时明确提示重新选择，未知创建与任务不重放。

宿主连接代次与原生运行时代次分别处理：原生连接仍有效的准确任务／观察订阅继续处理事件和交互；这不授予新任务派发资格。原生连接失效使其旧交互失效。完整时限、自测和真实验收遵循[HOST01 清单](../goals/20261029-1038-host-lifecycle-recovery.md)。

## REC01：准入状态与本地处置

施工契约：/status 与 /status <task-id> 分别显示任务结果和占用，等待项列出具体阻塞者、最后核验和下一步；离线显示最后记录及失效说明，不冒充刚刚核验。/stop 对 received 保留本地撤销，不能将 unknown 直接当未提交取消。

本地 CLI admission-report 与 admission-release 已有正式实现：默认只读，release 的 apply 必须准确任务、处置理由和报告 revision／确认摘要；消费者维护锁下执行原生只读核验和审计。无活动证据不足时拒绝，不提供全量解锁或 force；释放不改写 unknown、不调用原生执行、不发微信。操作见[运维](operations.md#rec01-候选的准入诊断与受控切换)。

## 微信独立选择原生会话

本人于 2026-11-07 明确要求实施以下行为：微信普通消息的目标由微信显式选择决定。桌面窗口焦点、标签切换或同一 Codex 进程内的 `/new`／恢复操作不自动改变微信选择。显式 `/focus`、`/cd`、`/new` 按各自契约改变目标；`/send` 只影响该条任务。2026-11-08 本人进一步明确 `/sessions` 只查询，退出输入目标使用 `/unfocus`。已经接收的任务始终关联接收时固定的原 thread。

当前 0.1.12 沿用原生身份契约：既有对话由注册 cwd 限定的后台列表、原生代次、准确 thread／native session、加载状态及正式订阅确认接入，不要求证明它当前显示在哪个窗口，也不读取页脚／标题来选身份。原终端来源可选，不伪造 endpoint。新建可见会话仍须自有启动进程回执与唯一原生握手，缺失或歧义时不 ready；实现与验收状态见 ROADMAP，不能将本契约视作正式 0.1.7 已去除首次显示依赖。

原目标卸载、原生断连或身份变化时，拒绝派发并提示微信；窗口或进程退出只触发重新核验原生可用性，不自动换目标，也不保证原 thread 仍能执行。不从存档恢复、复制历史或另建替代会话。原生接入失败或提交结果未知时按原协议说明状态，不把有 ID 或 loaded 当作执行成功，不重放未知输入。[TGT01 验证](validation/wechat-independent-target.md)保留历史验收，[原生身份契约](native-session-identity.md)说明当前实现边界。
