# 会话状态与异常通知

本专题是 P05／P13 的产品与技术契约。2026-11-15 本人授权实施；开发、验证与部署状态分别以 ROADMAP 为准。准确身份门禁见[身份契约](native-session-identity.md)，通知不得授予派发资格。

## 场景与影响

| 场景 | 主动通知 | 原因与动作 |
| --- | --- | --- |
| 仅退出 iTerm2，准确原生对象仍有效 | 无 | 保留输入目标与观察；宿主退出不等于原生会话退出 |
| 原生连接／恢复核验不足 30 秒，同代次原选择及订阅复验成功 | 无 | 静默恢复；旧数字列表和交互入口不沿用 |
| 连接／核验持续不可用至少 30 秒，有当前选择或未释放的活动任务 | 一次 | 区分连接中断和核验未完成，说明正在重试；不能说任务已停止 |
| 原生代次、准确 native session、cwd 变化，或准确 thread 已卸载 | 检出影响当前选择时一次 | 分别说明原因、输入／观察影响及重选方式 |
| 超时、发现不完整、身份缺失或订阅未确认 | 不确定性提示 | 只说尚未确认，不能称会话已关闭、删除或卸载 |
| 仅 last_managed 历史记录不可核验 | 无 | 不再复用该历史索引，不冒充当前选择失效 |
| 无输入目标、观察及活动任务 | 无连接异常通知 | 历史 unknown 且已释放占用不算活动任务 |

30 秒是固定默认值，不新增配置项；服务运行且事件循环可调度时每秒检查，不承诺睡眠／离线期间送达。会话问题在恢复核验及用户操作时检测，不新增全量历史扫描。不从用户退出 iTerm2、One 或窗口事件推断原生端重启原因。

## 文案与恢复

通知依次说明「原因、受影响角色和准确会话、下一步」。角色使用“输入目标”“观察订阅”；展示项目别名和稳定桥接编号，不将名称作为身份。原因限定为运行时变化、原生会话身份变化、未加载、项目目录变化、证据不足、订阅未确认、连接中断、核验未完成。不显示原始异常、RPC 正文、私人路径或任务内容。

- 运行时变化示例：“Codex 原生运行时已变化。输入目标：项目 · 会话编号。原选择未恢复。请先发送 /sessions，再用 /focus <序号> 重新选择。”
- 观察失败使用 /attach <序号>；两角色同时失败合并通知，未受影响角色明确保留。
- 持续连接故障：“Codex 连接暂时不可用……正在自动重连。”已连接但证据不足改为“会话恢复核验尚未完成”，不能冒充连接故障。
- 活动任务补充：“已提交任务的执行状态待核验，不会自动重跑；请用 /status 查询。”不宣称任务已停止或失败。
- 已发持续故障通知，且原选择及订阅全部准确恢复时，才补发一次恢复通知。只有任务时仅说明连接恢复，任务结果继续独立核对。选择未恢复不能称“会话已恢复”。
- /sessions 只刷新列表；输入使用 /focus，观察使用 /attach。无匹配项时先在原生客户端打开所需对话再刷新。unknown 不自动重放，投递重试不重新执行任务。

## 技术与持久化

恢复返回结构化原因，不解析异常文字、不用 stale 布尔值混合历史和当前角色。先核代次，再核准确 thread／native session／cwd／loaded；缺少候选不能直接认定卸载，只有准确读取或完整 loaded 快照支持对应结论。不得 resume 未加载对象来验证。

保持 schema 6／路由快照 version 2；routes.snapshot 的可选 session_notifications 保存故障 episode、开始时间、受影响角色、已通知阶段及至多两个角色问题。旧快照缺字段按空状态处理；普通选择写入保留通知字段。进程内延时同时使用单调时钟，重启继续持久化期限，时钟回拨不提前触发。

同事件后台重试、revision 增长和桥接重启不重复提醒；原因或角色／准确身份影响实质变化可补充一次。显式重选或退出对应角色结束旧角色问题，下次故障为新事件。连接复验完成结束连接 episode。通知状态、选择快照及冻结 Outbox 同事务提交，文本事务外走既有渲染层；失败回滚，投递 unknown 不自动重试。只保存有界当前通知状态，不增加无限通知历史。任务结果、交互和占用仍走各自流程。

同 episode 的每种角色原因只提醒一次，原因反复切换不重复。连接恢复时原子作废仍为 pending 的旧连接故障通知，避免微信上下文恢复后才发送过时故障；仅故障通知已 accepted／sending／unknown 时才追加必要恢复说明，这不证明本人手机实收。已开始或结果未知的投递不撤回、不自动重试。旧版本不维护新增通知字段，代码回退可能丢失去重状态，不能宣称跨旧版回退仍能去重。

宿主恢复沿用既有被动观察契约：仅目录／宿主证据缺失时保留已经确认的观察订阅，不因此授予新的派发资格；明确运行时换代或完整原生恢复核验失败时分别处理。通知功能不借机扩大订阅或恢复权限。

## 验收

离线覆盖历史单独失效、输入／观察分别和同时失效、同代次有效恢复、代次／session／cwd／loaded 变化、未知／超时／订阅失败、29.999／30 秒、重启／重复恢复／原因变化、无选择和已释放 unknown 静默、通知和路由原子失败、普通选择保留状态、重选后新故障、恢复文案及敏感异常不泄露。

真实原生生命周期与本人微信实收单独验收，离线通过不等于日常版本已加载。不为本轮实现操作本人微信或退出／重启业务程序。
