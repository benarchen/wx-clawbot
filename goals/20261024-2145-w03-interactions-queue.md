# W03：双端交互与原生队列

## 目标与预期行为

证明原终端与桥接共享审批和追问的原生裁决点，只接受首次有效答复，另一端解除等待。普通任务使用同一原生队列；查询、停止和交互答复不被任务阻塞。排队删除和运行中断必须有原生确认，提交回执丢失不自动重放。

## 背景与依赖

依赖已验收 W02，见 [验收记录](../docs/validation/w02.md)、[施工清单 W03](implementation-plan.md)、[开发契约 V03／V04](../docs/development-contracts.md)。基线 CLI 0.163.0、daemon 0.164.0。43 项当前测试及 W02 现场验证通过；微信真实通道属于后续 W04，不能把本地桥接驱动叫作微信真机收发。

## 确定决策与修改范围

- 只在两份既有临时 fixture 项目中新建 W03 专用可见终端；保留 W02 三轮证据端点，不向本人工作终端注入任务。
- 允许修改原生适配器、RPC、交互／任务协调与对应测试、脱敏验证记录；允许在 fixture 根目录读写明确的 `approval-*.txt`、`queue-*.txt` 测试产物，并先更新 fixture 的规则说明。
- 测试线程可使用单次只读沙箱、on-request 审批与 user reviewer，以取得真实人工审批请求；不改变模型、全局策略、认证、Skills、插件或原工作线程。
- 运行时负责双端裁决与实际排队，本地状态只作关联、类型校验和去重；不能用 SQLite 锁伪装桌面与桥接首次互斥。
- 全局配置继续按唯一获准信任项之后的摘要基线核对；不重启或替换 daemon，不执行全局更新、部署或外部消息发送。

## 检查点

1. 先用真实审批和追问验证事件是否共享、答复连接归属、原生 resolved 及另一端解除等待；字段以本机 schema 为准，存在字段不等于行为通过。
2. 实现请求 ID 类型、thread／turn／运行代次、公开请求 ID、期限与答复类型的明确关联；未知类型不自动批准。
3. 真实验证桥接先答、终端先答、同意／拒绝冲突、多题单选／自由文本追问、过期、断连迟到答复；记录原生接受结果，另一端同步关闭。本人已确认同题复选后置。
4. 核对原生 queuedSubmission 的关联 ID、queue ID 和实际 turn；验证忙碌时双方提交的顺序、排队删除、运行中断及回执丢失恢复。
5. 完成交互与任务协调的离线失败路径及控制命令不阻塞测试；保存能力矩阵和可重复现场检查入口。

补充核对：本人已明确保留双端统一排队硬要求。允许在专用窗口验证官方 `codex queue` 桌面提交入口与桥接是否共用原生队列；该实验不等于原 TUI 的 Tab 已统一，也不自动改变桌面产品入口。新增入口的正式体验须明确确认。

## 测试方法与失败路径

普通 unittest 只使用合成对端与内存／临时数据库，不触发真实终端或微信。现场脚本必须显式执行，启动请求先落私有记录，操作前验证端点与当前界面已就绪；禁止盲目发送 Enter。所有会改变测试任务状态的 RPC 保存稳定关联 ID，未知提交不重发。

V03 覆盖两端先答、冲突、答案无效、重复、过期、跨 thread、旧代次、断连后迟到和 UI 解除等待。V04 覆盖双方忙碌提交、FIFO 关系、超限、排队删除、原生中断、无回执与重连；不能用“停止输出”代替中断。

如果 native 请求只发单端、不能共享答复或原生追问形态不满足产品要求，记录具体请求、版本和失败证据，先核对官方实现；改变已确认体验必须另获明确决定，不静默降级。

## 验收标准

V03、V04 必须有真实原生请求、原生接受／完成状态及两端状态证据，全部关键分支通过；队列输入可关联实际 turn，无重复执行，取消有原生确认。相关单元、契约、编译与 diff 检查通过，文档及能力矩阵反映实际。达标后才完成 Goal 并进入 W04。

## 交付结果

阶段交付：交互代理、daemon 队列适配操作、离线失败路径与显式只读现场审计器；真实证据见 [W03 报告](../docs/validation/w03.md)、[脱敏审计](../docs/validation/w03.json)。启动参数导致独立运行时的问题已定位并移除。

验收器已移除未确认契约的参数覆盖路径，按真实消息顺序、独立完成的 turn 和对应输出判定原 TUI 场景；八项回归覆盖防止专用入口或不完整证据造成假通过。

V03 按本人确认的多题单选与自由文本契约真实通过；原生队列单独 FIFO、删除、运行中断和丢回执查询通过。原 TUI Tab 与 daemon 队列的独立任务要求在两个版本均失败；另有真正共用 daemon 队列的[桌面入口提案](../docs/desktop-queue-contract.md)，未以该提案默认替换正式要求。只有入口契约明确且 V04 达标后才能完成本 Goal；当前进度仅维护在 ROADMAP。

## 阻塞审计

连续三轮的同一阻塞为：当前原 TUI 与 daemon 不是同一任务队列，V04 的独立任务要求失败；本人保留硬要求，尚未确认专用入口契约。首轮真实验证两个版本并形成提案；第一轮续跑移除验收器契约覆盖路径，22:45 只读复核仍失败；第二轮续跑于 22:47 再次确认两个专用端点、原生历史与配置基线，失败不变。

本轮不依赖入口决定的检查点已完成并留证；继续改变桌面提交路径会跨越未决体验边界，重复同一任务不能修复客户端行为。恢复条件为本人明确入口契约，或原生客户端具备并真实通过同一队列的独立任务行为。未达到 Goal 完成标准，不进入 W04，也不合并或推送。
