### 总目录与初始化

1. 总目录是项目集合的父目录，例如 `~/project/`；它本身不注册为项目。新增注册范围限制在其真实直接子目录，本机与微信一致；任意外部目录注册、多个总目录及运行中更换总目录不纳入本 Goal。
2. 仅枚举一层目录项；不读取项目内容、不要求 Git、不递归、不为检测项目而打开子目录。隐藏目录同样只作为目录项候选，不擅自把“所有文件夹”改成仅 Git 或可见文件夹。
3. 在任何深入访问前按项目规则排除 `openclaw-local` 及其大小写变体；不得读取其内容、配置或凭据，也不得通过链接别名把其纳入注册。其他不合格项列明原因；不以探测其内容帮助判定。
4. 不可访问、重名、非法别名、指向总目录外或非直接子目录的符号链接均不自动注册。目录内链接须规范化并校验真实层级、去重和禁止范围；悬空链接明确报告，不沿链接深入扫描。
5. 初始化预览给出总目录、拟新增项、保留项、跳过项及原因。提交绑定准确预览摘要，目录项、路径身份或既有清单变化后要求重新预览；不得悄悄使用变化后的扫描结果。限额或超时须明示，不把截断列表当完整扫描。
6. 初始化是显式一次性导入，不在每次启动、查询或重连时重扫注册。取消注册后目录仍在，也不能自动复活；后来创建的目录须显式 add。扫描不自动创建可操作会话。
7. 旧配置升级保留准确别名、真实目录及原选择；不在升级时自动初始化或覆盖。尚未设置总目录时，旧查询／会话能力保持，新增命令明确提示先初始化；已登记的历史外部目录可保留，不借兼容扩大新注册范围。
8. 允许初始化无合格项目或移除最后一个项目，形成明确的零项目状态。帮助、项目管理和微信通道仍可用；会话相关命令提示没有已注册项目，不访问首个不存在的项目，不自动挑选其他目录。

### 查询、添加与取消注册

- list 对应原 `/projects` 的用途；“可用”只表示目录可访问，不代表 Git、Codex 会话、订阅或任务已就绪。check 展开注册诊断，不宣称原生能力检查通过。两者不写配置、不改变路由、不启动 iTerm2／Codex、不触发任务对账。
- add 必须先证明目录在允许的真实范围内、别名与真实目录无冲突；同一别名与目录已存在时返回“已注册”并保持原版本，不重复写入。相同别名指向不同目录或不同别名指向同一真实目录时拒绝，不自动替换。
- remove 仅按准确别名匹配；不存在时返回“未注册”且无写入，不将模糊目录名或会话序号解释为项目。没有 force、批量删除、重命名或迁移任务入口。
- remove 的阻塞条件包含该项目的输入目标、观察订阅、尚未完成的选择／可见创建意图、已接收但未派发的任务、原生提交中／排队／执行任务、未完成交互及等待／持有占用。提示具体阻塞类别和正常处理入口；不替用户 unfocus、detach、stop 或清锁。
- 已结任务、已结交互、投递记录和无活动占用的历史 unknown 不作为永久阻塞条件；它们仍须保留并可查询／投递／对账。不能因取消注册丢弃延迟结果或把 unknown 改成失败／成功。未选中的空闲原生会话存在本身不阻塞取消注册，也不因此关闭它。
- 删除后会话列表旧序号不能再授予访问；注册变更使本次会话列表快照失效，提示重新 `/sessions`，不自动刷新或重排后沿用旧序号。其他项目准确输入目标与观察订阅保持。
- 当前目录或已知目录记录指向被移除项目而无阻塞选择时，明确清除其选择资格，不自动切到另一个项目；重新注册也不能恢复旧会话授权。新目标仍须完整原生复验。

## 工程方案与一致性要求

| 编号 | 施工决策／约束 |
| --- | --- |
| E01 | 延续一份私有配置作为项目注册权威来源，不新增第二份项目数据库。总目录、格式版本及必要修订信息在同一配置协议中设计；旧纯 projects 格式可读取，新格式只在显式管理动作时写入。SQLite schema 6 与原生协议原则上不变；确有迁移需求须先单独说明并取得对应授权 |
| E02 | 提炼一套有实际行为的注册服务，CLI 与微信共用校验、预览、变更和诊断；按 config、命令、运行生命周期的既有分层接入，不把注册写入放进微信通道或复制两套规则。优先标准库，不新增无必要依赖 |
| E03 | 桥接运行时由准确私有实例串行处理注册变更；本机 CLI 经仅当前用户可访问的本地 Unix IPC 向同一实例请求，微信直接调用同一服务。复用已有准确进程、代次和消费者核验；IPC 仅接受有界的项目管理协议，不开放通用文件或 Shell 执行，不监听网络 |
| E04 | 桥接停止时本机 CLI 可在本项目私有锁保护下修改；锁内再次核对消费者与实例，运行中或身份不确定时不能绕过 IPC 写文件。启动也遵循同一写入协调约定，防止“检查时未运行、写入时已启动”。连接超时不得推定进程不存在，不自动重启桥接 |
| E05 | 显式指定或已发现实例的配置／state-dir 不一致时拒绝变更，不悄悄修改默认文件。IPC 验证所有者、私有路径权限、运行代次、协议字段、消息长度与超时；旧 socket、伪造／越权连接或重连不能接管注册写入 |
| E06 | 写前校验并保存权限受控的原配置备份；锁内比较准确修订／文件摘要，使用同目录临时文件、刷新及原子替换，失败不留下半份文件。检测到外部手改时停止覆盖并诊断；不承诺任意手工编辑热加载，不保留静默最后写入者获胜 |
| E07 | Routes、SessionCatalog、BridgeRuntime、当前及离线控制器、恢复／原生重连都消费同一已提交注册快照。成功须同时满足持久化和当前运行态安装完成；不能只写文件后回复成功，也不能重连恢复旧构造参数中的注册清单 |
| E08 | 注册变更与目标选择、任务接收／预留、派发、目录纳入和可见创建使用可核验的一致性边界。remove 检查与提交之间不能插入新任务；已 prepare 的旧请求提交前复验修订及注册资格，过期请求拒绝，不误投其他项目。新 add 不切换现有输入目标 |
| E09 | 精确规定“持久化成功、内存尚未安装”及崩溃／回执丢失的处理：受影响旧运行态不能继续派发，依据已提交快照收敛并在恢复时核验。请求具有可核对的结果标识；超时提示结果待核对，不自动重放写操作。旧配置备份不能在已有后续变更时直接覆盖恢复 |
| E10 | 注册变更不强制重新订阅原生、不释放已有订阅、不创建任务；现有订阅和已接收任务继续绑定准确原生对象。native／iTerm2 不在线不妨碍纯注册操作；阻塞状态无法可靠确定时拒绝 remove，不以离线为由忽略保护 |

G02 交付必须将 E01 至 E10 落到准确字段、接口、锁顺序、提交点、异常矩阵及有界资源限制，再开始跨模块编码。发现需要偏离已确认的产品边界或扩大权限时，先列出具体差异与影响；普通实现细节由 Agent 自主确定并记录，不把未决架构问题交给子 Agent。

## 范围与禁止事项

- 允许改动与本 Goal 直接相关的配置解析／模板、CLI 与微信命令、注册服务及必要本地 IPC、路由／目录发现／运行生命周期／恢复接入、测试和相关文档。新增正式目录先明确结构职责；临时夹具、报告及制品放 `.tmp/prj01-project-management/`。
- 不创建或删除业务目录，不初始化 Git，不改变项目文件和原生聊天历史，不自动启动／退出 iTerm2、Codex 或微信；不引入新会话创建／恢复方式，不读取状态栏或标题识别身份。
- 不读取／使用被禁止项目的代码、配置、凭据和服务；不修改 Codex 全局配置或其他项目服务。扫描只触及准许范围内的一层目录项和必要路径元数据。
- 不借注册能力扩展多用户、群聊、Web UI、云端管理、多总目录、任意外部路径注册、总目录搬迁、项目重命名、自动监控扫描或批量强制移除。
- 注册范围仍是桥接路由边界，不是操作系统沙箱；原生准确身份、loaded／订阅、队列权威、规则加载限制及 unknown 不重放保持。
- 不自动修改日常私有配置、生产账本、launchd 或发布版本。隔离新格式配置可用于测试；真实业务根初始化／变更、手机发送及生产切换按具体对象和动作另行授权。清单内示例不是操作授权。
