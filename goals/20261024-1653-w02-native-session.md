# W02：原终端与同一原生会话

## 目标与预期行为

桥接经正式 Codex Unix WebSocket 接口连接原运行时，准确关联 iTerm2 端点、进程身份、runtime 与 thread。专用终端先发、桥接再发、终端继续时，三轮上下文和 native thread 不变。

## 背景、依赖与入口

依赖已验收 W00、W01；[协议基线](../docs/protocol-baseline.md) 记录 CLI 0.163.0、运行时 0.164.0。见 [开发契约 V01／V02](../docs/development-contracts.md)、[施工清单 W02](implementation-plan.md)。SDK API 连接曾被拒绝，用户启用后才能验证真实宿主链路。

## 决策与修改范围

只连接既有 runtime，不启动替代 daemon；代理与原终端共用 native thread。允许增加 Agent 最小接口、WebSocket JSON-RPC 连接、宿主发现、端点证据核验与对应测试和文档；在两个项目内临时测试目录创建专用可见测试终端。禁止读取其他项目凭据、修改全局配置、向工作终端注入任务、复制历史或另开后台会话冒充成功。

## 检查点

1. 实现有界、异步 WebSocket JSON-RPC 连接，区分通知、请求、错误与断连；代理退出不杀原 runtime。
2. 真实 initialize 握手，只查询专用项目范围；确认支持版本与消息字段，不读取其他会话正文。
3. SDK 发现端点并通过稳定 ID 与进程证据核验，覆盖 Shell、退出、PID 重用及同目录多终端；缺少证据时明确 unbound。
4. 创建两个临时测试项目及专用终端；验证桌面、桥接、桌面三轮，保存脱敏身份与结果证据。

## 测试与失败路径

离线协议对端测试覆盖并发响应、请求 ID 类型、连接关闭、畸形消息、超时晚回执、未知请求；不能将其视为 V01／V02。真实初始化、SDK、终端和三轮测试显式执行。API 未启用时等待用户步骤；运行时不提供映射时调查正式接口，不凭 cwd／标题猜测。

## 验收标准

V01、V02 的真实终端、进程、运行时与 thread 证据完整；普通 Shell 和过期端点不能误投。三轮同一会话、原终端仍可操作；没有未解释的版本或关联错误。未达到时保持 Goal 未完成，不启动依赖它的 W03。

## 交付结果

已实现原生 WebSocket RPC、socket 与版本校验、只读 CLI 及宿主候选端点检查。23 项离线测试通过；现有 daemon 真实 initialize 成功。首次 JSONL 原型超时的原因与修正依据见 [证据](../docs/native-session-evidence.md)。两个私有临时项目已准备。iTerm2 API 启用仍待用户步骤，V01／V02 未通过，本 Goal 保持未完成，不进入 W03。

补充交付：进程身份改用 macOS 原生微秒级启动时间与 TTY 设备号，结构 ABI 经本机 SDK 编译对照一致；自身进程真实读取稳定，补充 PID 重用、端点退出与无效宿主 PID 边界测试。当前测试结果与阻塞状态见 ROADMAP。

实施核对：`app-server proxy` 仅透传原始字节，不能直接写 JSONL。Unix 控制 socket 使用 WebSocket；桥接直连该 socket，不新建运行时。见 [官方固定源码](https://github.com/openai/codex/blob/970111f6cb62cc02fe36a82ea7d71b37a2889c97/codex-rs/stdio-to-uds/src/lib.rs)。
