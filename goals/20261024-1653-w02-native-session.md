# W02：原终端与同一原生会话

## 目标与预期行为

桥接经正式 Codex Unix WebSocket 接口连接原运行时，准确关联 iTerm2 端点、进程身份、runtime 与 thread。专用终端先发、桥接再发、终端继续时，三轮上下文和 native thread 不变。

## 背景、依赖与入口

依赖已验收 W00、W01；[协议基线](../docs/protocol-baseline.md) 记录 CLI 0.163.0、运行时 0.164.0。见 [开发契约 V01／V02](../docs/development-contracts.md)、[施工清单 W02](implementation-plan.md)。SDK API 连接曾被拒绝，用户启用后才能验证真实宿主链路。

## 决策与修改范围

只连接既有 runtime，不启动替代 daemon；代理与原终端共用 native thread。允许增加 Agent 最小接口、WebSocket JSON-RPC 连接、宿主发现、端点证据核验与对应测试和文档；在两个项目内临时测试目录创建专用可见测试终端。禁止读取其他项目凭据、向工作终端注入任务、复制历史或另开后台会话冒充成功。全局配置只允许按本人新增授权添加 wx-clawbot 根目录的 `trust_level = "trusted"`，其他内容、模型、认证、Skills 和插件保持不变。

## 检查点

1. 实现有界、异步 WebSocket JSON-RPC 连接，区分通知、请求、错误与断连；代理退出不杀原 runtime。
2. 真实 initialize 握手，只查询专用项目范围；确认支持版本与消息字段，不读取其他会话正文。
3. SDK 发现端点并通过稳定 ID 与进程证据核验，覆盖 Shell、退出、PID 重用及同目录多终端；缺少证据时明确 unbound。
4. 创建两个临时测试项目及专用终端；验证桌面、桥接、桌面三轮，保存脱敏身份与结果证据。

## 测试与失败路径

离线协议对端测试覆盖并发响应、请求 ID 类型、连接关闭、畸形消息、超时晚回执、未知请求；不能将其视为 V01／V02。真实初始化、SDK、终端和三轮测试显式执行。API 未启用时等待用户步骤；运行时不提供映射时调查正式接口，不凭 cwd／标题猜测。

## 验收标准

V01、V02 的真实终端、进程、运行时与 thread 证据完整；普通 Shell 和过期端点不能误投。三轮同一会话、原终端仍可操作；没有未解释的版本或关联错误。未达到时保持 Goal 未完成，不启动依赖它的 W03。

新增 Agent 最小适配接口、空闲轮次提交、绑定复核和显式只读现场验收器。43 项离线／合成对端测试、编译与 diff 检查通过；现场验收器重新读取宿主和原生历史后通过，不信任本地 passed 字段。GUI 关联与新 TUI 启动使用本机 daemon 模式，避免 --remote 对本机子目录采用精确信任规则。

初始化的唯一额外授权为本人明确要求新增 wx-clawbot 根目录的 trust_level = "trusted"。写入保留全部原字节，TOML 语义仅增加该项；当前摘要与增量后基线一致，模型、认证、Skills、插件均未修改。授权及故障定位细节见 [原生连接证据](../docs/native-session-evidence.md)。
