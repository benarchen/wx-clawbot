## 3．开工前必须冻结的实现决策

### 3.1 R01 停止候选语义

- 裸 `/stop` 仅在当前冻结目标中，从完整 waiting／holding 占用对应的非终态任务判断候选；零条或多条均要求准确 ID，零原生取消／中断。
- released unknown 不自动回到裸停止候选，也不冒充 completed；其未知结果、历史对账与迟到活动重新占用保护继续保留。
- 准确 ID 入口保留原有完整目标复验和取消／中断条件，不因这次候选查询优化获得新的历史派发或停止资格。
- received 撤销与原生开始竞争继续以事务及原生终态裁决；不得先返回取消成功再异步尝试落库。

### 3.2 R02 有界分页与失败语义

采用现有 thread/list cursor 的有界完整分页，不直接切换成绕过完整桌面活动发现的捷径。首个候选预算为每页最多 100 条、每个准确 cwd 最多 10 页／1000 条；单轮最多 256 个端点、64 个列表页／4096 个唯一 thread，列表响应累计编码大小最多 32 MiB，发现总时限 25 秒。预算同时生效，以最先达到者为界；若官方固定 schema 或真实证据不支持相关字段，先记录阻塞，不猜接口。

必须核对响应形态、ID／cwd／状态、重复 thread、cursor 类型／循环／空值、页数／条数／字节及总时限；同 ID 出现矛盾记录不能覆盖。缓存限单次发现，不能复用上轮成功作为新身份凭据。

只有完整发现、准确进程／TTY／可见 thread／runtime／session／cwd 全部核验后才原子替换 catalog。任一必要范围失败，不用部分结果授予准入；当前路由与数字列表不可静默重定向。等待任务发现失败时保留明确原因与未提交状态，不杀死维护循环或重复提交。

预算不是性能提升声明。G01 先用合成规模验证可行性；需要改变这些边界时先写明证据和取舍，不在测量失败后悄悄放宽。并发优化另在 G07 基于测量实施，不提前并行化宿主 SDK 调用。

### 3.3 R05 制品与运行目录

开发继续使用独立检出／项目虚拟环境；生产目标采用 `<private-state>/releases/<version>-<artifact-digest>/` 下的版本化环境，wheel 非 editable 安装。制品包含项目本身，运行依赖按现有精确哈希锁安装；不打包凭据、数据库、终端身份或开发工作树。

同一版本环境使用确定解释器、安装包和相对包文件摘要，启动及子进程加载可交叉核对。禁止通过 PYTHONPATH、开发路径、当前 cwd 或 `.tmp` 补充正式运行包。release manifest 明确区分 wheel SHA-256、源码树摘要、安装包文件摘要和依赖锁摘要，不能用一个摘要混称全部对象；不得包含真实身份和私有配置正文。

原 Label、同一私有状态根、本人绑定及正常停止／异常恢复语义保持。生成的托管操作卡只变更本项目准确 ProgramArguments／WorkingDirectory 等必要字段，其他设置保留并逐项列出；不管理 Codex／iTerm2 的重启。

本轮预计仅修复版本 0.1.3，schema 保持 6；G00 核对版本是否已被其他工作占用，最终版本按实际冻结，不提前宣称发布。默认不增加数据库结构。若实现确需 schema 改动，先停止相关路径并说明新增数据范围，不以版本隔离为由隐式迁移。

### 3.4 性能决策原则

先建立前后可运行的同机基准，不以新修复使原本失败的案例成功冒充速度提升。未发生瓶颈或优化会破坏身份／结果保证时，允许交付“该场景无需改动”的完整测量结论，不强行重构。

控制时延与发现／历史查询总耗时分别统计；注入的网络／模型等待不混算成本机 CPU 收益，也不能通过扣除真实本机等待美化结果。所有未优化场景仍需给出容量、调用次数、预算及拒绝行为。

## 5．性能测量协议与接受门槛

| 场景 | 最小输入矩阵 | 记录与判定 |
| --- | --- | --- |
| 多终端发现 | 1／8／16 个已注册候选端点；1／100／101／1000 个 cwd 会话；目标在首／末页；跨项目共享仓库与不相关端点；另测 257 端点、循环 cursor 和整体预算超限 | 正常范围完整发现；页／条／字节／时间预算可核对，超限明确拒绝且零派发；报告每阶段及总耗时、RPC／进程查询数量 |
| 长历史恢复 | 本地账本 0／10000／100000 条已结历史，活动占用保持 1／16 条；原生准确 turn 位于最新／第 50／第 200 页，另测越界、重复 client、多输入、活动工具及换代 | 结果恢复／占用释放／未知保留分别核对；不把少查必要页数当收益，不使用全量历史替代活动查询 |
| 并发短渲染与控制 | 固定 1／8／32 个并发渲染调用，输入 1／8／63 KiB；另测 64 KiB 子进程阈值、超长结果、取消与事件突发；控制命令与正常工作交叠 | CPU、wall、RSS、线程／子进程及 pending 峰值、控制 p95／最大值和取消后回收；控制不能被普通结果等待阻塞 |

纯本机计算微基准至少 1 次预热、7 组交替配对测量；固定输入与 seed，保留每组原始结果及中位数、p95。每个宣称优化的指标，中位数改善至少 10％且超出本轮配对波动；未满足则不宣称有效收益，决定继续定位或保留原实现。基线原本失败的场景只记录失败／成功，不计算提速比例。

本地合成 peer 端到端混合负载至少持续 120 秒，记录样本数、控制／交互接收至处理完成的完整本地 wall time，门槛为 p95 ≤ 50 毫秒、最大值 ≤ 250 毫秒；该统计使用明确无外部网络／模型等待的固定场景，不是公网 SLA。每轮至少 100 个控制样本，样本不足判无效。至少用两轮独立负载复核候选稳定性。

相同有效输入下，候选主要未优化场景的配对中位数不应退化超过 10％；峰值 RSS 不应无解释增长超过 10％，且 120 秒负载最后 30 秒的活动任务／worker／事件队列不能持续净增长。增加安全核验导致的必要成本必须明列并在 G06／G07 裁决，不能通过删校验达标。机器噪声需保留原始数据并用相同协议复核，不事后选择性删除慢样本或下调门槛。
