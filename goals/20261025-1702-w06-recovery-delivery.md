# W06：持久化、可靠回执与故障恢复

## 目标与预期行为

执行状态与投递状态分别持久化；服务断连或崩溃后先核对准确原生任务，不自动重跑未知任务。恢复路由、会话归属和交互失效状态，输出有界、分段有序，控制命令不等待普通任务。通过本阶段 P09 至 P11、P13 与 V07／V08 后交付，不将替身测试当成真实原生故障证据。

## 背景与文件入口

依赖已验收 W03、W04、W05。入口为 [施工清单](implementation-plan.md)、[契约第 5／6／8／9 节](../docs/development-contracts.md)、[架构](../docs/architecture-design.md)、[产品](../docs/product-design.md)、[W05 证据](../docs/validation/w05.md)。现有 `runtime_state.py` 仅为初始 schema 1，`controller.py`／`execution.py`／`service.py`／`delivery.py` 已真实连通微信与原生会话；路由、交互及部分事件索引仍在内存。真实运行库已有本人验收数据，不能当空库重建。

## 依赖与已确定决策

- 沿用 iTerm2、Codex 原生共享 daemon 和专用桌面队列契约，不复制历史、不另开后台 thread、不修改全局配置、认证、Skills、插件或模型。
- 原生 queue／client／thread／turn 为执行裁决依据；RPC 与 SQLite 不具备跨系统事务。发送 unknown 不作已失败重发，执行 unknown 不作未执行重投。用户新的请求使用新的稳定来源身份。
- 接收与游标、任务终态与最终回执分别保持事务；数据库经单独有界工作通道，持有本人通道唯一消费者锁。
- 路由恢复重新核验原端点、进程、当前页脚 ID、运行时与原生 session；旧交互连接代次失效，不沿用已过期答复。attach／detach 继续采用已确认的独立观察订阅。
- 准入覆盖同项目／仓库与 worktree 的冲突，默认建议最多两个桥接活动项目、每会话十条队列。外部桌面任务不能由桥接器强制阻止，检测到冲突时停止新增桥接派发并明确报告。
- 正文与日志必须有上限，保留期及清理对象明示；不删除未核对的关键结果，不碰 Codex 历史或业务数据。代码、命令、路径、URL 与用户原文不因自然语言排版改变。
- 自然回复上下文过期与 guixu／wx-clawbot 真实项目验收仍保留 W08，不以本 Goal 的故障替身代替。

## 允许修改与禁止事项

允许修改本项目状态、路由、执行、发送、CLI、测试和受影响文档，新增必要的 schema 升级实现、故障注入器与性能测量入口。使用项目虚拟环境与已有依赖，不默认委派。

真实 schema 1 运行库的升级须遵循施工清单“未来迁移真实运行数据遵循单独授权边界”。先完成可审阅升级代码、合成库验证、备份／检查方案，再就具体升级对象与语句请求授权；授权前不对真实运行库执行 DDL、不覆盖或删除其数据。项目内合成测试库的创建与升级属于本次实现范围。

仅操作任务自有测试进程、临时项目和专用终端；可按故障检查点中断本任务前台桥接，保留原生终端，不停止任何既有服务。禁止访问其他项目微信凭据及 openclaw-local 的任何代码、配置、凭据和服务。真实消息、身份、数据库、备份、日志、截图和原生会话记录不得进入 Git。

## 检查点

1. 核对现有 schema、路由／交互生命周期及错误状态；固定所需字段、不变量、升级步骤和准入边界，先以合成数据验证。
2. 实现持久化路由与交互、同来源准入去重、项目互斥及原生未知任务核对。重启不重放旧命令，不能核对时明确 unknown；连接代次失效关闭旧答复。
3. 实现回执的分段、顺序、优先级、过时进度合并、发送结果核对和受控重试；仅重发可确认未送达的结果，不从发送路径调用执行。定位微信换行显示问题，明确实测边界。
4. 准备真实运行库升级的具体可审阅结果，获得授权后执行必要备份、原地版本升级与只读核验；不改写历史或清空验收数据。
5. 在两份专用临时项目执行 V07：提交意图后／RPC 回执前后、终态与 Outbox 提交后、HTTP 发送前后受控中断，核对原生实际执行次数、结果恢复和终端保留。模拟通道与真实微信分开记录。
6. 执行 V08：两个会话各十条上限、持续原生事件、长轮询断连和长输出；记录本地控制 p95、队列／事件上界、内存趋势及测量口径。目标 p95 小于一秒，排除模型和公网时间；不把目标值写成结果。

## 测试方法与关键失败路径

离线回归覆盖重复／冲突来源、版本／绑定不匹配、升级回滚、磁盘写入失败、终态与回执事务、丢失 RPC 回执、原生已完成但本地未知、目标切换／退出、跨项目冲突、满队列、取消与交互竞争、重复发送及超长文本。测试发现数量必须非零，普通测试不得操作真实微信或用户终端。

真实故障仅针对任务自有进程和测试会话。每个副作用前保存唯一意图，未知结果先检查同一句柄、数据库及准确原生记录；不因观察超时重启或重投。真实微信收发只面向已确认的本人绑定，网络错误与业务拒绝分开，未获本人确认不声称手机收到。

## 验收标准

- P09 至 P11、P13 和 V07／V08 有与范围相符的行为证据；真实接口与合成故障分别标注。
- 已执行任务不重新运行，未知任务不自动重放；投递恢复保留准确来源、顺序和最终错误，不能反向触发执行。
- 同项目冲突、队列满、状态未知、交互过期与断连均有明确状态及下一步；控制处理不排在普通执行后。
- 有限队列、事件、正文与日志策略落实，长输出保留关键内容，性能数字可复现、真实限制不隐瞒。
- schema 升级保留原数据与私密权限并有授权记录；必要测试、编译、diff、文档链接及公开内容检查通过。

## 交付结果

满足以上标准后记录实际行为、真实故障／性能结果、升级验证与限制；进度只在 [ROADMAP](../ROADMAP.md) 维护。

### 真实库升级的审阅边界

schema 2 的具体增量为 routes、interactions、delivery_attempts 三表，以及 inbox.body_sha256、outbox.body_sha256 两列和必要索引；回填摘要与旧投递尝试来源，不删除或改写原有业务字段。实现与失败回滚见 [schema.py](../src/wx_clawbot/schema.py)，状态语义见[账本说明](../docs/state-schema.md)。升级动作须取得本人的具体授权，停止本任务前台消费者后备份核对再执行，不停止原生终端或其他服务。输出、资源、真实恢复和性能关卡仍须继续，不能以结构升级完成本 Goal。
