## 真实接口检查

- 本机官方 `codex app-server daemon --help`／`version` 核对：只读 version 返回运行中的 socket、原生可执行文件及两个版本字段。正式 `serve` 自动发现后仍执行原生握手和同一 Codex home 核验；不安装或启动替代运行时。
- Python 3.14.5、iTerm2 SDK 2.30、CLI 0.163.0／daemon 0.164.0，Git 可用。`doctor --config … --state-dir … --iterm2` 成功，确认两份临时项目、iTerm2 API 与私有账本权限；输出不含路径、认证响应、消息或本人身份。
- 在新建的专用 iTerm2 页面按正式安装入口运行 `wx-clawbot serve --config …`，没有手填 socket／原生可执行文件。连续两轮完成：`status=running`、`doctor`、`stop_requested`、`status=stopped`。7 个既有专用 Codex 进程的 PID、微秒启动时间、可执行文件和 TTY 身份均一致；原有 9 条任务仍全部 completed，全局配置摘要匹配批准基线。没有向原生会话注入任务或由验收器发送微信。
- 使用不存在的专用 socket 验证启动失败：非零退出，组件 agent、类型 FileNotFoundError，输出没有测试路径。用户工作终端未接收输入。
- `plutil -lint config/launchd.example.plist` 通过；模板 RunAtLoad／KeepAlive 为 false，argv 为数组、无凭据，日志默认 `/dev/null`。未注册、启动或卸载任何 launchd 服务。

显式验收入口为 [w07_operations.py](../../tests/integration/w07_operations.py)，需指定两份专用项目配置、fixture root、私有报告目录并确认专用终端范围。它拒绝已有消费者及重复报告，不自动重复未知启动。首次验收器在完成启动／退出后因 Python 时间元组与 JSON 列表类型差异误报进程变化；独立只读复核 7 个身份一致，修正序列化比较后另一次完整两轮通过。失败记录保留，未用进程存在代替业务任务成功。

## 离线检查与边界

291 项 unittest discover 测试实际执行通过，编译、diff 检查通过。新增覆盖只读状态不改变任务／发送状态、陈旧或复用 PID 不接受停止、旧代次不停止新实例、退出记录不误删替代记录、重试写入受消费者锁保护且不触发其他任务恢复、版本与组件错误脱敏、模板语义。原生 RPC 离线测试使用专用 Unix socket，不自动连接微信或用户终端。

操作员 `retry-reply` 的新 CLI 路径只在合成数据上执行写入；真实“结果重试不重新执行”已由 [W06](w06.md) 独立验证，W07 没有重试任何其他真实 unknown 回执。`status=running` 仅证明本项目实例与消费者锁有效，不等同通道即时送达或任务成功。HTTP 工作线程可延迟进程完全退出，使用者应等待状态而非立即重复启动。
