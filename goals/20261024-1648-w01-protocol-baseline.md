# W01：依赖与协议基线

## 目标与预期行为

固定本机 Python、Codex 和 SDK 组合，提供可重建的哈希锁及只读诊断；以本机 schema 和上游固定提交建立后续原生实验输入。

## 背景、依赖与入口

依赖已验收 W00；见 [施工清单 W01](implementation-plan.md)、[开发契约](../docs/development-contracts.md)、[技术决策](../docs/technical-decisions.md)。版本和字段以实施时查询为准；文档存在不能代替动态验收。

## 决策与范围

允许安装项目内依赖、生成 schema、固定公开参考源码、编写诊断和契约测试；只读尝试 iTerm2 API 与现有 daemon 版本。禁止修改全局配置、自动启用 API、重启 daemon、读取私人会话正文、访问旧独立项目或发送微信。

## 检查点

1. 查询 SDK 官方发布、源码、许可证、维护活动与 issue；选定兼容版本。
2. 在 .venv 安装、导入；精确锁定直接及传递依赖和哈希，以第二个临时虚拟环境验证重建。
3. 生成 Codex 0.163.0 稳定／实验 schema，提取使用字段脱敏 fixture 并校验；固定腾讯公开参考 commit、版本、许可证与关键文件摘要。
4. 实现只读 SDK 与版本诊断；保留连接错误的真实类别，不把未启用 API 当成功。

## 测试与关键失败路径

依赖导入与隔离重建，schema 字段契约，缺失／版本不匹配／API 不可达诊断；确认测试实际发现。真实 SDK 连接单独记录，连接缺权限时请求具体设置，继续完成无依赖项。

## 验收标准

锁文件可重建，fixture 来自固定版本且无私人数据，维护和许可证证据可追溯；SDK 动态连接已测试且结果明确，环境门禁可明确保留为 W02 前置条件。

## 交付结果

锁定 iterm2 2.30、protobuf 7.36.2、websockets 17.3 并成功隔离重建；CLI 0.163.0 与 daemon 0.164.0 分别生成 schema，保存最小契约与摘要；腾讯参考固定提交与六份文件摘要已记录。9 项离线测试、编译与 diff 检查通过；只读 SDK 连接实际失败，API 启用作为 W02 前置条件保留。证据见 [协议基线](../docs/protocol-baseline.md)。
