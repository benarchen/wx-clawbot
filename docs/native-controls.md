## 微信入口与范围

| 入口 | 含义 |
| --- | --- |
| `/model` | 查询选中原生会话的模型和推理强度 |
| `/model list` | 查询当前已连接运行时的模型目录，无需选择会话 |
| `/model set <模型名称> [推理强度]` | 同次设置模型及推理；省略使用所选模型的目录默认 |
| `/fast` | 查询当前档位与 Fast 支持情况，不 toggle |
| `/fast on`、`/fast off` | 请求显式开启／关闭，仅影响选中会话 |
| `/codex status` | 查询原生设置、运行／队列及确实可取得的用量 |

0.1.12 已实现上述修改入口，原生版本／准确目标／忙碌／交互／占用／容量与确认条件不满足时明确拒绝或保留未知。0.169.0 已有联合设置、默认／显式推理、同值、Fast、手机及桌面后续采用、busy 拒绝和最终清理证据；旧单字段候选证据保留原适用范围。`/status` 仍是桥接任务／占用／投递查询；`/help` 增加“Codex 原生命令”，不创建 `/codex help` 或把帮助冒充原生功能。每条用途尽量不超过 20 字。

## 身份与读取

### 默认展示约定

本人于 2026-11-14 要求在同一 NCM01 工作中优化全部命令的可读性。状态与设置回执按“结论／目标、设置、额度”分组，使用简短加粗标题和独立段落；微信会折叠普通单换行，不依赖空格对齐、宽表格或密集行内代码。模型名称仅展示一次，模型目录按条目分隔，保留准确可输入名称、支持等级及目录默认，不重复展示近似 displayName。

`/codex status` 默认显示模型、思考等级、Fast 开关、会话状态及账号额度；“思考等级”对应 reasoningEffort，“Fast”对应已核验的原生服务档位设置。状态使用“空闲／忙碌／异常”等人类可读用语，非空队列显示等待任务数。未知值明确标注，不把缺失当作关闭／空闲／零额度。思考等级保留可输入英文值并配中文说明，完整选项见模型目录。

默认隐藏会话 token／原始 totalTokens／turn ID／上下文上限、完整会话编号及重复来源说明，内部准确事件缓存与身份核验不变，不新增诊断命令。账号额度仍保持账号范围与原生桶来源，未知适用模型不猜测；重置时间和一次查询时点明确使用北京时间。会话用项目、目录名及展示用短编号区分；项目别名与目录名完全相同时只显示一次，不同时保留两者，不做大小写折叠或修改原名称。短编号不用于路由或操作授权；完整会话标识保留在会话列表，任务／审批／追问所需完整编号继续展示。Fast 回执保留“仅设置确认”边界，未知结果仍明确“不重放／不回滚”，不因美化隐藏失败或竞争风险。

本次一并检查 `/sessions`、选择／观察回执、任务进度／结果、`/status` 和 `/help` 的分组及措辞；只改渲染文本，不改解析、路由、准入、原生 RPC、意图和投递语义。验证包含异常／缺失值、Markdown 字面值、长名称／多段、默认隐藏统计及操作编号保留；静态预览不冒充微信真机通过。

除目录查询外必须有微信输入目标，并完整复验注册资格、目标修订、daemon 代次、thread／native session、cwd／provider、loaded 与已有 route 订阅。只存在 observer 不授予输入目标；桌面切换不改微信目标。查询不写设置、配置或任务，不启动 iTerm2／daemon。

匹配 0.167.0 schema 的模型目录包含推理选项、defaultReasoningEffort、serviceTiers、defaultServiceTier；目录最多 10 页／1000 项／2 MiB，循环／重复或超限明确失败。每个名称和 ID 均有边界；只作为运行时提供候选，不保证账号实际推理访问。Fast 识别以目录中的 Fast 名称及该条目的原生 id 为准，未知／歧义不猜测。

当前设置的完整快照来源是原有 loaded-only 订阅路径：请求前后核验准确 loaded 对象，以没有任何设置覆盖参数的 thread/resume 响应读取有效 model／reasoningEffort／serviceTier，不从全局 config、历史 turn、标题／页脚猜。只对同一连接已核验的 route 订阅读取；首次合法订阅和之后的快照读取均不得加载 notLoaded 存档。模型／推理在前后读取间变化应拒绝本次快照。0.167.0 双临时项目实测确认快照可随设置变化且不修改全局配置；同一候选已补充即时 TUI 观察，具体差异见下段，不能扩写为桌面显示一致性已通过。

读取边界复核：前后 loaded 检查不是服务端条件式 resume。0.169.0 专用原生已验证：订阅保持时关闭 TUI 仍 loaded；另一连接归档会卸载会话，但即使归档发生在 loaded 检查与 resume 之间，原生仍明确拒绝 resume 已归档对象，随后独立核验没有重新加载。此两条真实路径未复现存档恢复，现有控制逻辑保持；离线回归覆盖读取途中卸载拒绝和归档错误不自动 unarchive／重试。结论限本次版本与关闭／归档路径，不推广到所有卸载机制或未来版本，详见[原生验证](validation/native-settings-lifecycle.md)。此前已接受的设置写入竞争边界与此读取验证分别保留。

同一候选 Controller 实测后，A 的即时屏幕采样仍显示原模型，准确原生 turn_context 已采用微信命令程序设置的新模型／推理。该次只采样一次，未证明之后是否自动刷新；桌面标签不能作为当前设置或会话身份权威，也不强制重绘 TUI。后续查询以原生新快照为准，桌面客户端另行操作仍可能改变同一 thread 的设置；本人手机验收中的专用 TUI 手动标记已有准确 turn_context 后续采用证据。

字段缺失不等于 null／默认或零。内部 token 观测仅取准确已订阅 thread／turn 的 tokenUsage 事件，带时点、类型／非负校验和有界缓存；默认 status 按上述展示约定隐藏这些诊断明细，新连接不恢复旧缓存当实时，不猜上下文百分比。账号额度通过当前运行时的 account/rateLimits/read 只读快照取得，使用 excludeResetCreditDetails=true，不传支持 Reserve 的实验参数；不刷新认证、不切换账号或调用重置／余额／计费操作。账号多桶保留原生标签和提供的适用模型，不猜桶与所选模型映射；缺失／失败明确提示，显示查询时点，不缓存旧额度当当前值。真实只读及本人手机额度实收均已通过。

## 写入前置门禁

thread/settings/update 的空 object 不是生效证明。必须先证明当前值读取、精确匹配的设置通知／回读与当前 turn、已有队列、桌面并发修改的裁决边界，才能接入真实写请求。桥接锁不能冒充跨桌面原子互斥；参数未指定字段须保持，模型设置明确发送 model 和 effort，必须保留 tier／provider；Fast 只发送 serviceTier。目录 Fast ID 与关闭 null／默认含义逐版本核验，不硬编码 priority／fast。

0.167.0 专用实测中，目录提供 Fast ID；清除 serviceTier 覆盖的 null 请求回读归一为 default，显式设置 default 也得到设置事件及回读确认。因此查询将实际 default 显示为“未开启（原生标准档位）”，不能把 default 与 null 当作同一原始字段值，也不能把清除覆盖泛化为任何账号的关闭策略。

原生会接受 active 且有排队项时的设置更新；已有排队任务在开始时采用更新后的推理值，没有入队设置快照或条件写保护。本轮精确 turn_context 证明正在执行的任务保持 medium、随后排队任务采用 high。原严格队列保护因此存在能力缺口；本人已明确接受下段边界，候选实现不再承诺检查后的桌面原子保护，历史缺口不能改写为严格保护已解决。另有模型／推理采用字段，但 turn_context 和 Turn 不提供实际请求服务档位；Fast 的设置确认不等于实际请求档位、提速或计费证明。

本人于 2026-11-10 明确接受的边界：桥接拒绝所有已知原生／桥接忙碌及排队写请求，并协调桥接自身的接收、派发与选择；桌面可在检查后并发操作，无法保证既有队列不受影响，冲突或不确定结果明确提示，不回滚／重放。Fast 仅承诺准确原生设置的事件与回读确认，实际请求档位未提供时明确说明。当前实现和分层验收均按此边界，不免除身份与真实关卡。

设置意图在 RPC 前私有持久化，用于去重与未确认状态；不得把控制记录作为设置权威、混入项目注册配置或伪造 Agent 任务。当前候选已实现最小 ControlJournal，不新增数据库表或迁移；未知不重放、同值明确设定非 toggle、失败不改投或回滚其他客户端的新值。

### 已固定的写实现契约

本人于 2026-11-11 确认统一 `/model set <模型名称> [推理强度]`。省略等级从当次模型目录的 defaultReasoningEffort 取值；默认缺失或不在支持列表时拒绝并要求显式指定，不继承当前推理或猜全局值。模型与推理在一个请求中发送并同时确认，部分应用为 unknown，不保证原子写、不回滚。无变更也须同时匹配两值，回执显示两值及默认／显式来源；目录展示默认值与支持等级。旧直写模型及 reasoning flag 不再接受，历史验收不扩写为新入口通过。

本人接受边界后，G02 采用已取得的逐字段事件／回读、模型／推理采用与原生竞争证据作为写实现依据；后续工程及手机关卡仍必须执行。锁序沿用项目管理 gate → 会话 changes → 执行 admission_gate，文件 lease 仅覆盖本地读改写，不跨网络 await。接收时记录普通任务预留，写前检查预留、原生状态与完整队列、有效占用和未结交互；准入派发和设置不能穿透同一桥接锁。事件继续由原有唯一消费者分发，设置窗口在发送 RPC 前登记，限定准确 thread／连接代次和有界事件数量，异常／冲突／字段缺失不能确认成功。

SQLite 保持 schema 6。私有运行目录增加 native-controls/，按源消息 SHA-256 命名独立 JSON，每条最多 16 KiB、最多 2048 条，目录 0700／文件 0600，原子写入并 fsync 文件和目录。短文件 lease 处理创建及终态更新；容量满或损坏时拒绝新增写，不自动删除去重证据。记录仅含请求摘要、准确目标、原设置、显式字段映射、phase／确认状态和冻结回执，不保存凭据、普通任务内容或第二份默认设置。

RPC 前提交 intent；同一消息命中任何既有记录均不再发送。confirmed／unchanged／rejected 返回冻结回执，intent／unknown 说明待核对，不能因新连接或当前值相同重放旧命令。明确原生拒绝也须回读证明原值未变才可记 rejected；超时、断连、取消、通知不全、并发或落盘失败保留未确认。原生 ACK、准确事件和有效回读共同确认当前设置，不能据同值事件宣称排除所有桌面同值竞争；设置确认不表示已影响某个特定任务。Fast off 使用 0.167.0／0.169.0 各自真实核验的显式 default，不对其他档位或版本猜测清除行为。
