# sessions 纯查询与微信帮助核对

2026-11-08，按本人要求修复开发树的 `/sessions` 查询边界，并逐项核对微信 `/help`。发布基线为 0.1.8，交付状态见 [ROADMAP](../../ROADMAP.md)；本记录不表示本机已经切换版本。

## 根因与修复

旧控制器把 `/sessions` 当作选择事务：刷新后释放原目标的 route 订阅，`Routes.snapshot()` 清除 focused／managed 目标并增加 revision，再持久化路由。若终端已关闭且没有其他订阅，释放最后一个订阅可能导致原生对象随后卸载；查询本身并没有删除聊天记录。旧路径还会恢复宿主、核对未知启动和触发任务结果对账。

当前实现将查询分离到 `Controller._query_sessions()`：有界发现并更新内存数字列表，保留目标、模式、目录、revision、观察、last_managed 和持久化选择；不订阅／退订、不恢复选择、不核对创建或任务结果，不启动 iTerm2。查询仍正常接收消息、记录已处理和冻结回执，这些 Inbox／Outbox 写入不等于修改会话选择。原生离线明确失败，不把未取得证据说成空列表。

查询期间普通消息可冻结原目标并独立派发复验；空结果、关键词筛选或原目标已不在列表中不清除原选择，也不代表原目标仍可执行。失败／超时／换代保留原列表及原有效期，不把旧列表续期。成功刷新后按新列表序号选择，序号默认十分钟有效；原数字列表不会跨连接恢复。

`/unfocus`／`/uf` 保持显式退出输入目标的职责，仅释放 route 角色，保留观察和已接收任务。若 route 是最后一个订阅，原生对象仍可能随后卸载，不能将退出输入理解为删除历史或永久保活。原生离线的选择／观察变更继续拒绝，未新增离线改写路由能力。

源码入口：[控制器](../../src/wx_clawbot/controller.py)、[内存路由](../../src/wx_clawbot/routing.py)、[目录](../../src/wx_clawbot/catalog.py)、[共享订阅](../../src/wx_clawbot/subscriptions.py)。

## help 逐项核对

以[解析器](../../src/wx_clawbot/commands.py)、控制器、[任务控制](../../src/wx_clawbot/execution.py)、[离线行为](../../src/wx_clawbot/runtime_lifecycle.py)、[同步交互](../../src/wx_clawbot/interactions.py)与[异步答复](../../src/wx_clawbot/async_questions.py)为实现证据；共 15 个命令、6 个别名。帮助增加必要前置与失败边界，未扩展命令语法或原生能力。

| 命令及别名 | 核对结果／帮助补齐 |
| --- | --- |
| `/help` | 显示固定说明；补齐自身入口、必填／可选记号、未知命令不执行 Shell |
| `/projects` | 仅注册项目与本地目录状态，不扫描所有仓库 |
| `/cd` | 注册范围内路径／别名，复用准确同 cwd 受管对象；无候选可见创建；多个候选无法确定时拒绝，不自动选择非受管对象 |
| `/new` | 已有当前目录，可选标题最多 128 字符；自有可见创建并选中，窗口出现不当 ready |
| `/sessions`、`/ss` | 改为纯查询；明确筛选、发现范围、无宿主启动，以及序号十分钟有效与稳定编号区别 |
| `/focus`、`/f` | 明确选择后续普通消息目标，原生身份／订阅核验后提交；桌面变化不改投 |
| `/unfocus`、`/uf` | 显式退出输入目标；观察、已接收任务与终端保留 |
| `/attach`、`/a` | 独立观察后续桌面任务及交互；最多一个，替换须明确，不改输入目标或重放历史 |
| `/detach`、`/ua` | 仅退观察，保留输入目标及已接收任务 |
| `/send`、`/s` | 按快照序号单发，保持输入目标；普通文本／单张静态 JPEG／PNG 与同消息图文边界保持 |
| `/status` | 区分总览与准确任务状态；总览含投递汇总，带 ID 不宣称重发完整结果或显示所有同步交互详情；离线标最后记录 |
| `/stop` | 明确本地撤销、原生队列删除和运行中断；省略 ID 要有当前目标唯一有效候选，准确 ID 含 t-；不撤销已有副作用 |
| `/approve`、`/deny` | 准确 r- 同步审批的一次性决定，非永久许可，q- 异步问题不能用来审批 |
| `/answer` | r- 同步多题为回答数组，q- 异步多题为字符串；单题文本、准确 ID、入口期限与失效拒绝分别明确 |

异步补充仍受现有版本门禁约束，不承诺跨端首答互斥，也不代表任务暂停。帮助中的格式／能力只作入口说明，详细规则仍由[命令契约](../command-contract-proposal.md)维护。原 H2 显式层级的微信渲染保持，不在本轮改动排版方案。

## 回归与验收

| 检查 | 实际结果 |
| --- | --- |
| 旧实现复现 | 将原 controller／routing 放入隔离临时包，运行同一组 3 个新回归：列表保留选择、空结果保留目标、离线不启动宿主，全部出现预期断言失败，无测试错误 |
| 控制器新边界 | focused／managed、持久化选择、观察／任务角色、last_managed 不变；无 host ensure／verified、选择恢复、启动核对、任务 reconcile 或 route 保存调用 |
| 失败与并发 | 空结果、筛选、发现失败、超时、原生代次变化、退役取消、查询中普通消息及显式 unfocus 通过 |
| 目录与身份组合 | 使用真实 SessionCatalog／身份验证实现及模拟原生端，宿主缺席时查询 B 仍向选中的 A 派发；A 卸载后查询仅列 B，仍保留 A 且拒绝派发、不改投 B |
| 任务对账分离 | 查询不改 unknown 结果；独立执行既有 reconcile 后可核对准确终态，不重放任务。常驻恢复工作者保持运行 |
| 帮助覆盖 | 15 个命令、6 个别名均在帮助中且解析样例通过；经当前输出渲染链得到 1 段、1499 字符，命令和两类 JSON 示例完整，未发送真实微信 |
| 最终工程检查 | 765 项测试／40.097 秒，零失败、零错误、零跳过；编译、依赖、文档链接／锚点／JSON 和差异检查通过 |
| 跨文档 | 项目规范、README、PRD、开发契约、命令、ADR、图片说明、运维、测试和追溯同步；保留历史 Goal／验收正文及 DOC01 已验快照 |

初次沙箱完整检查有 17 项本地 Unix socket bind 被权限拒绝，不能算通过；正常本机权限下完整重跑通过。随后补充两项目录／身份组合回归并完善帮助边界，最终再次完整通过上述 765 项。私有原始日志保留于 `.tmp/sessions-query/`，正式实现和文档不依赖这些临时文件。

## 本轮边界

未调用真实微信、原生执行或用户终端，未修改生产账本、全局配置、部署或 Git 引用。本轮为离线开发验收，不冒充手机实收或真实原生动态复测。原生协议与加载判定未变，仍需每次派发完整复验。

冷启动后额外保留普通 Shell 由本人要求后续处理，本轮没有修改宿主启动／窗口创建逻辑。提交、发布与本机切换未执行；日常独立制品仍按既有 0.1.8 运行，微信端需部署新制品后才会使用本次行为。
