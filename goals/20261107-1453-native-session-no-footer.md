## 计划采用的行为与实现决策

以下为本清单的目标契约，已在 G01 先行固定规范；实现与验收按检查点推进，不能将契约固定当成能力完成。README 在能力完成必要验证后才更新为当前事实。

1. **用户选择准确原生对话。** 后台列表中的“既有原生会话”表示指定已核验 daemon 中、注册范围内的准确 thread，不再声称它正在某个 iTerm2 窗口显示。标题、最近活动、短 ID 和目录用于辨认；实际路由固定完整 ID，不以这些展示字段猜测身份。
2. **原生身份独立于宿主来源。** 运行时代次、准确 thread、native session 与规范化 cwd 是原生核验字段；原终端／进程证据保留为可见创建、来源诊断及资源清理依据，不再给所有既有 thread 强造 terminal／PID。禁止用空 endpoint、虚构进程或随意绑定某个窗口满足旧类型约束。
3. **关闭窗口不自动改投或判定成功。** 桌面焦点、标签、同进程切换、terminal ID 变化或终端退出均不自动改变微信目标。原 thread 仍在准确原生运行时加载、能确认订阅与接入时可继续；若随之卸载／原生断连，则明确拒绝或报告未知。是否继续由原生证据决定，不承诺关闭终端后必然可执行。
4. **只选择已有加载对象。** 既有对话必须先在当前运行时确认已加载，再获取准确订阅与队列能力；不得用 `thread/resume` 把 notLoaded 存档加载出来后宣称原对象一直可用。既有适配器用于订阅的同名协议调用须保留调用前／后准确身份与 loaded 核验。
5. **新建可见对话仍使用自有启动流程。** 先持久化 launch 意图，再创建准确自有终端；结合 boot PID／启动时间／TTY／可执行文件、项目、同一原生代次、不可预测的单次 launch 标记、唯一原生启动轮次及完成回复建立关联。不读页脚／标题／滚动历史来识别 thread。零个或多个候选保持未就绪，超时或失去回执不再次创建。
6. **发现有范围和预算。** 先确定许可 cwd 集合，再进行项目过滤和已加载交集，不能先把所有私人历史正文抓回再过滤。候选来源优先使用注册根、微信明确选中的合法 cwd、受管登记，以及 SDK 提供的注册范围内进程 cwd 等非读屏证据，不遍历磁盘猜目录。精确 cwd 不能声称覆盖全部子目录；G00 必须明确验证已注册合法子目录的发现入口和未枚举范围的用户提示。无法安全枚举时报告发现范围或不完整，不静默漏会话后声称已完整核验。
7. **显示信息不是执行证据。** 列表可缺少标题或最近活动字段，以可辨识默认文案补足；相同标题／目录的多段对话分别展示。多个 TUI 显示同一准确原生 thread 时，去重为同一个路由对象；跨 daemon、cwd 或 native session 不合并。
8. **命令与旧任务契约保持。** `/focus` 选普通消息目标，`/send` 单次派发，`/attach` 独立观察，`/detach` 只退订；`/sessions`／`/unfocus` 仍退出输入聚焦，`/cd` 复用受管会话而不顺带创建替代已有失败对象。接收时冻结完整目标，后续切换不迁移队列。
9. **恢复不等于重新发现后自动选一个。** 桥接重启而原生代次不变时，重新核对准确身份、项目、加载状态与订阅后恢复原选择；原生换代、native session 变化或旧记录缺证据时提示重新选择，不按标题、目录、最近活动恢复。unknown、历史结果对账与准入占用继续遵守原契约。
10. **稳定编号与兼容显式处理。** 新桥接编号基于准确原生身份与项目，不含桌面 endpoint、标题、时间或列表位置；同一原生代次内刷新及桥接重启不任意变化。native session 根 ID 不能替代 thread。既有持久化编号和任务关联不得批量重写；缺少原生字段的旧选择可以保留原记录并通知失效，但历史结果／占用对账不得因此永久失联。

发现预算沿用现有 25 秒总时限、每 cwd 十页、总 64 页、4096 条与 32 MiB，控制候选 cwd 不超过 256 个；微信快照仍最多 100 条。loaded 查询也保留有界分页。超限、重复或循环游标均拒绝不完整结果，不能静默截断或无限等待；必要调整须有测量证据和文档说明，不添加一组未经需要的新配置项。

## 修改范围与明确排除

- 允许修改上述身份、目录、启动、选择、订阅、恢复与准入中直接相关的实现和测试，按当前结构最小改动；优先复用现有标准库和依赖，不新建无行为框架，不顺手重构其他模块。
- 不修改原生 Codex CLI，不依赖官方新增接口、终端标题 ID、Hooks 或 OCR，不用日志时间戳、最近活跃线程、文件占用或模型复述猜测目标。
- 不新增后台 Codex 副本，不复制历史，不自动加载／恢复存档，不跨 daemon 接入，不改变模型、认证、Skills、插件或项目规则加载责任。
- 默认不增加依赖或数据库表／列，优先使用已存在的映射与版本化快照。若确认必须改 schema，先形成具体差异、兼容读取、迁移／备份／失败恢复和验证材料，另行取得相应授权；不得直接改生产 schema 或通过清空旧选择／unknown 绕过兼容问题。
- 当前计划不替换 0.1.7 正式制品，不编辑真实 `.env`、私有配置、凭据、LaunchAgent 或 Codex 全局设置。单进程测试隐藏状态栏需隔离使用，并核对参数是否影响 daemon 复用；不得为试验保存新的全局信任项或自动接受授权提示。
- 不扩展图片、异步追问、桌面统一队列等独立功能；必须回归其现有目标关联与边界。原生不消费队列时如实报告状态，不强制开始或重发任务。
- 不委派。若以后明确授权多 Agent，必须先补齐逐项子任务目标、接口、依赖、修改边界、失败路径和交付定义。

## 真实原生验证安排

1. 使用 `.tmp/native-session-no-footer/<round>/` 保存任务私有数据和意图；默认一个专用窗口、至多两个清楚命名的标签，记录本轮所有 window／terminal／进程。优先两个专用临时项目；若必须保存新的全局信任才可继续，则不自动接受，记录限制并在既有授权的本项目做只读替代试验，禁止把不同范围写成相同证据。
2. 用匹配版本支持的单进程设置，从 TUI 启动前隐藏两种 ID、标题不含 ID。核对设置不会偷偷转到独立 daemon；保留 global 配置／凭据／托管定义摘要。不编辑真实 `tui.status_line`，不修改用户工作终端。
3. 分别构造“候选启动前已存在且已加载的 A”和“候选创建的 B”，不能只测自己新建 B 就声称已覆盖既有对话首次接入。候选控制器首次选 A 时没有预先读取 ID 建立的桥接绑定；允许原生测试器在私有证据中核对准确原生身份。
4. 用隔离合成微信入站与 SQLite／Outbox、真实原生队列闭环：A 先记住私有随机标记，首次接入后不在追问中提供原值，准确 A 回忆；显式选 B、回 A，核对各 client／turn、原生终态、零串投、无额外 thread。握手后的业务验证只读且零工具，不把生成回执当成手机已送达。
5. 保持订阅时验证 A→B 的桌面切换；随后正常停止并重建候选桥接验证同代次恢复。另行测试断开观察连接可能导致卸载的失败路径，不为让其通过强行 resume。daemon 换代与崩溃默认用离线／合成协议对端验证，不重启用户共享 daemon。
6. 在准确自有资源空闲、队列为空且本地无未知任务后，验证终端关闭的两种原生状态，再清理已确认归属的测试资源。无法确认任务终态时先保留现场、只读对账，不强制清理。
7. 核对正式制品与生产账本没有被本试验直接修改，配置、凭据、Codex 全局设置和托管定义保持。原始私有 ID、消息和屏幕证据不入 Git；公开报告仅用脱敏布尔、数量、步骤和结果。
