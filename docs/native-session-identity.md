# 原生会话身份与宿主来源

TGT02 候选已完成双路径真实原生接入、切换、恢复与关闭／卸载验收，冻结检查状态见[交付记录](validation/native-session-no-footer.md)。本文件描述候选行为，不表示日常已部署；正式 0.1.7 的历史边界见[TGT01](validation/wechat-independent-target.md)，唯一进度源为 [ROADMAP](../ROADMAP.md)。

## 选择与证据

微信选择的是指定已核验 daemon 中的一段准确原生对话，程序使用完整 thread ID。原生 sessionId 可能为根身份，不能代替派生对话各自的 thread。必需核验原生连接代次、准确 thread／native session、规范化注册 cwd、加载状态与正式订阅／队列能力；窗口标题、最近活动和短 ID 只帮助用户辨认。

既有对话不宣称对应某个当前显示的终端。可选宿主证据记录真实 terminal ID、PID／启动时间、TTY 和可执行文件；没有证明来源就不填写，不构造空值或假 endpoint。派发不读页脚、终端标题、滚动历史或日志猜 ID，不修改全局显示设置。

可见创建仍通过准确自有进程回执和唯一不可预测 launch 标记关联原生启动轮次，核对项目、原生代次、准确输入与 completed 回复，不只看 preview。零个／多个候选、fork、错项目、未知创建或缺失完成证据不能 ready，不重复创建或重放。

## 发现范围与编号

后端按精确 cwd 查询。候选包括注册根、明确选择的合法 cwd、受管登记，以及可用 SDK 返回的注册范围内进程 cwd；不读取屏幕，不遍历磁盘或抓取全量私人历史。列表提示其范围；根目录查询不等于子目录递归覆盖。未知子目录不能静默视为已完整核验，预算不足明确失败。

发现沿用 25 秒、每 cwd 十页、总 64 页／4096 条／32 MiB，cwd 候选上限 256，微信快照上限 100。分页重复、循环、越界、超限或不完整不能授予派发资格。多个端点显示同一 thread 时去重；跨 runtime、native session 或项目的对象不合并。

新稳定桥接编号使用 `native-v1`、socket 设备／inode、完整 thread、native session 与规范 cwd 生成 UUID5，前缀仍为 `s-`；不依赖 terminal／PID、标题、排序或最近活动。派发前和查询前后复查当前 socket 归属、权限与设备／inode，同路径换代撤销旧资格并触发连接失败。

路由快照提升为 version 2，补充 `runtime_identity` 和 `native_session_id`，SQLite 仍为 schema 6，没有迁移。version 1 仅在真实 SDK 端点／进程和准确原生身份可重建原有完整 UUID5 指纹时恢复为新编号；不按标题、cwd 或 ID 片段猜映射。无法恢复的原 target／observer 另存 `unrestored_selection` 供诊断，不作为路由来源；旧任务与冻结回执保留原编号，不批量改写。旧数字列表均失效，需重新获取。

## 生命周期、恢复与历史结果

桌面切换、终端改 ID 或退出不自动改变微信目标；原 thread 仍可准确核验且加载时可以继续，若卸载／断连则明确失败或未知。新业务输入与接收时的完整目标冻结，后续 focus 不迁移旧队列。

同原生代次的桥接重启要完整复验原选择并获得订阅确认；代次或 native session 变化、缺少持久化证据则不自动恢复。后台 loaded 只是可用性证据，订阅／入队／执行／回执分别核对；不得把 notLoaded 对象恢复后当作持续运行。实测退订后并非立即卸载，需以当时的原生状态为准。

历史结果、仓库占用与新任务资格分离。旧路由失效或 thread 为 notLoaded 时，历史结果仍可只读核对准确 thread／cwd、当前元数据身份稳定、唯一原 client／turn 及终态；合并输入、重复 client、缺身份或错目录保持 unknown。该路径不订阅、不 resume、不授予新派发资格，不改冻结目标。占用继续使用原有准确终态、完整队列和审计条件；不清锁或清库迁就新模型。
