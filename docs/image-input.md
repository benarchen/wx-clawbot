# 微信图片输入使用指南

单图输入、私有附件及原生队列已完成真实微信验证，包括看图、桌面／微信连续追问、目标切换、忙碌排队、取消、中断和故障恢复。下载在独立子进程中执行，超时后结束并回收该子进程。本次交付范围为单图，同消息图文经本人明确后置。实际启用状态及后续事项见 [ROADMAP](../ROADMAP.md) 和 [验收记录](validation/image-input.md)。

## 使用前提

- 使用本项目已确认的本人微信绑定，电脑运行、联网，iTerm2 和原生 Codex 会话可用。
- 原生图片版本准入为 0.165.0／0.166.0；其他已支持版本维持原文本范围，图片会明确拒绝。0.166.0 的版本协议与现场验证范围另见 [HOST01 记录](validation/host-lifecycle-recovery.md)。模型本身也须支持图片，桥接不自动换模型或运行时。
- 新版桥接使用 schema 3。已有 schema 1／2 必须在明确安排下停止前台、检查并备份升级；serve 不自动迁移。具体见 [账本升级](state-schema.md)。
- 目标 Codex 状态栏显示完整 Session ID；身份无法核验时不接收图片任务。

## 发一张图片

在微信逐条发送并等待明确回执：

```text
/sessions
/focus 1
```

`1` 必须换成本次列表中想继续的准确会话。随后直接发送一张普通静态图片。没有说明文字时，桥接加入固定的结合当前上下文分析提示；图片文字本身不构成执行命令或审批授权，模型仍遵循项目规则和已有用户指令。

任务会经过接收、准备、原生排队、执行和最终结果。收到“正在准备”或“已进入原生队列”不表示已经看完，最终以准确终态和正文为准。

支持静态 JPEG／PNG，每条原始消息最多一张，密文及明文各不超过 10 MiB，解码后不超过 2000 万像素。不自动转换、压缩或只取缩略图来绕过上限。

## 图片与说明如何关联

解析器可以保留同一原始消息内的文字与一张图，但本次微信客户端实际将一起发送的图片和说明拆成两条消息。同消息图文尚未获得真机证据，已按本人决定列入项目待办；日常按下述分开发送方式操作，两条消息是两个独立任务。

若分开发图和说明，先等图片收到接收回执，再向同一目标发送说明，例如：

```text
重点分析刚才截图右下角的报错，先给原因和建议，不修改文件。
```

这是同会话的下一条独立任务，依靠原生上下文关联图片，不按时间窗自动拼接。如果期间切换 focus，说明进入新目标；继续原图前应选回原会话。

含图消息中的 `/stop` 等斜杠文字作为图文任务正文，不执行桥接控制命令。状态、停止、审批和追问答复应单独发送纯文本命令。

## 目标、排队与取消

| 操作或情况 | 行为 |
| --- | --- |
| 没有执行目标 | 提示先选择会话，不下载、不执行 |
| 只有 attach | 观察订阅不成为图片执行目标 |
| 下载时切换 focus | 已收图片仍绑定原目标，不迁移项目 |
| 同会话先图后文字 | 后到文字不会越过尚未准备好的图片 |
| 目标忙碌 | 准备完成后进入原生队列，文件保留至可确认的终态 |
| `/status` | 查看目标、任务 ID、执行和回执状态 |
| `/stop <任务ID>` | 准备中撤销，排队时准确取消，运行时请求中断并等待终态 |

`/sessions` 会退出输入聚焦，编号有效期十分钟，查完需要重新 `/focus`。`/unfocus`、`/detach` 不取消已接收任务。中断也不撤销此前已发生的效果。

任务 ID 要完整保留 `t-` 前缀，例如 `/stop t-<回执中的完整编号>`；省略前缀会提示任务不存在。只在当前目标恰好有一条未结束任务时，单独 `/stop` 才能确定目标，否则必须给出完整 ID。任务先自然完成时，停止不会将它改成 interrupted。`/sessions` 是复数，`/session` 不是有效命令。

## 常见失败与恢复

| 提示 | 处理 |
| --- | --- |
| 未选择目标或身份无法核验 | 核对原终端完整 Session ID，刷新列表并选择准确会话 |
| 图片输入尚未核验 | 核对实际 daemon 版本，不只看 CLI，不静默升级 |
| 下载失败或超过时限 | 核对网络；沿用系统已有 HTTPS CONNECT 代理，不修改代理设置 |
| CDN 地址未通过核验 | 保留失败记录查协议，不开放任意 URL、私网直连或重定向 |
| 图片损坏、不支持或超限 | 确认单张静态 JPEG／PNG 及大小、像素；失败时不只执行文字 |
| 附件预算已满 | 查看显式维护计划；不删除排队、运行或 unknown 附件腾空间 |
| 模型拒绝图片 | 查看原生错误，不换模型、另开视觉会话或去图重跑 |
| 执行或投递 unknown | 先核对原终端和任务，不把未知视为未执行或未收件 |

重启仅允许明确尚未尝试原生提交、且原目标重新核验通过的图片任务继续准备与首次准入。已尝试提交者只读对账；旧普通 inbox 命令不重放。

仅回执发送失败时，按 [运维说明](operations.md) 检查 retry-reply；它只准备结果重投，不重新执行图片任务。

## 图片保存与维护

图片保存在本项目私有运行目录的 attachments，不进入业务仓库、源码或任务临时目录。目录 0700、文件 0600。最多两个并发准备，附件预算 256 MiB；临时文件也计入，目录达到 1024 项时拒绝新增准备。

默认不自动删除历史。maintain-state 默认只读，明确 `--apply` 时已结正文与附件按七天、摘要按三十天处理。排队、运行、unknown 和关键结果未送达者受保护。文件删除在数据库释放决定提交后执行，磁盘失败保留可重试引用。

Codex 历史可能内联保存图片；清理桥接附件不删除原生历史，也不能撤回模型已读取内容。下载参数和密钥在准备完成或明确失败后从附件记录清除，不写常规日志。

本次不支持多图组合、相册、引用旧图、动态图片、图片作为普通文件上传、其他媒体、图片回传或生成。不支持消息整条拒绝，不截取第一张或只执行文字。旧文本版本已经过滤的图片不自动补回。

完整交付状态及同消息图文的保留项见 [IMG01](../goals/20261028-1135-image-input.md)；W08 自然上下文失效／恢复独立保留。
