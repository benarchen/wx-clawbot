# W02：原终端与同一原生会话验收

机器可读结果见 [w02.json](w02.json)，逐项检查入口为 [现场验收器](../../tests/integration/w02_verify.py)。这是 W02 的技术原型验收，不是 P01 至 P14 的完整产品验收；项目进度只见 [ROADMAP](../../ROADMAP.md)。

## 真实行为

基线为本机 CLI 0.163.0、已运行共享 daemon 0.164.0、iTerm2 3.7.6、Python 3.14.5 和已锁定的 SDK 2.30。

| 关卡 | 操作与实际证据 |
| --- | --- |
| V01：四方关联 | SDK terminal ID 与 macOS PID、微秒级启动身份、TTY 设备号关联；同一 socket 代次的 native thread 中出现该专用终端启动时的唯一随机输入，随后核对 native session ID。目录和标题不作为唯一身份。 |
| V01：同目录双会话 | 同一临时项目启动两个原生终端，各自的随机输入精确命中不同 thread；主会话推进三轮，另一个保持一轮，没有串投。 |
| V01：普通 Shell／退出端点 | 普通 Shell 在实际发现结果和 validate 中均被拒绝；关闭已完成的重复测试端点后，旧 terminal／process 配对不能再通过。 |
| V01：独立运行时 | 在专用 iTerm2 终端运行 `--no-daemon`，用唯一输入定位其真实 thread。共享 daemon 报告 notLoaded；适配器在发 resume 前拒绝，复核后仍为 notLoaded，没有恢复副本。 |
| V02：项目 A | 原终端第一轮记住随机词，桥接第二轮回忆并添加新标记，原终端第三轮回忆前两轮；原终端、PID／启动身份、TTY、runtime、thread、native session、目录、模型和 provider 不变。 |
| V02：项目 B | 在另一临时项目独立完成相同三轮流程，三轮均为 completed，原终端可继续输入且显示桥接结果。 |

普通用户工作终端没有接收试验输入。没有用屏幕输出代替任务终态：任务完成以原生完成事件或原生历史 completed 状态为依据。第一项目第三轮曾遇观察连接超时，后来只读核对既有历史恢复证据，没有重发正文或执行任务。第二项目收到了桥接和桌面两轮原生完成事件。

## 复核与复现

普通测试不访问真实终端：

```sh
.venv/bin/python -m unittest discover -s tests -v
```

现场验收显式执行：

```sh
.venv/bin/python tests/integration/w02_verify.py --live \
  --record /absolute/path/to/private/w02-record.json
```

记录仅保存在私有测试工作目录，不进入版本管理。记录包含 SDK 创建回执中的 terminal ID、启动时的 PID／微秒与 TTY、经 native 用户输入核验的 thread／session ID、运行时代次、各轮随机标记以及唯一获准信任增量之后的配置摘要；字段要求由验收器直接读取并验证。`passed` 一类本地字段不作为通过依据，验收器会重查宿主和原生历史，缺记录、零候选、端点消失或少一轮都失败。该工具自身不创建会话、注入输入或发模型任务。

重新构造场景时，在项目内临时目录准备两份独立 fixture，先启动可见原生终端并正常完成第一轮，再订阅该已加载 thread。启动使用 `native_tui_command` 构造的本机 daemon 模式及已核对的 CODEX_HOME，保留用户模型；不能用 `--remote` 冒充同样的本机目录信任语义。更新检查仅在测试子进程中关闭，不能向未经就绪确认的终端发送 Enter。普通文本和 Enter 分开发送，目标端点必须先核对。

## 验证边界

- 此原型要求显式的身份核验／绑定证据。发现一个 Codex 进程不等于自动绑定任意既有 thread；未核验的端点保持 unbound，不猜测。微信侧选择及首次绑定的交互属于 W05。
- PID 同秒重用、畸形协议、版本不匹配、订阅拒绝、断连、超时迟到响应和队列溢出等边界由离线及合成对端测试覆盖；真实宿主、三轮与独立运行时拒绝由上述现场操作覆盖，两者分开记录。
- 本人明确授权的唯一全局增量为当前项目信任项，写入保留原字节，TOML 结构差异只有该条；此后验收使用新增后的摘要基线。程序没有修改模型、认证、Skills 或插件，也没有复制这些内容到仓库。
- 现场有既有 Codex hooks 返回 code 7 的警告；本任务没有读取或修改相关 hook，原生模型轮次完成不能推断 hooks 成功。SDK 使用 websockets.legacy 的弃用警告也保持可见，不通过屏蔽日志制造“无警告”。
- 早期独立运行时样例未确认就绪便输入命令，且端点后来消失，该样例作废。重做样例在测试进程关闭更新检查后取得独立 thread 证据；已核对全局 CLI 仍为 0.163.0，未发现匹配的 npm 全局更新日志。

双端审批／追问、队列与中断属于 W03；此处的通过不能替代那些关卡。
