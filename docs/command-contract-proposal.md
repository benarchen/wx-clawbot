# attach／detach 命令契约

本文经本人于 2026-10-25 明确选择“采用独立观察订阅”确认，定义 [产品设计](product-design.md) 中对应命令的行为；确认契约不表示实现或验收完成。文件路径保留，避免破坏已有引用。

`focus` 已有明确职责：选择后续普通文本的执行目标。若把 attach 也定义为选择目标，它与 focus 没有独立行为；排他接管、强停桌面、后台迁移均与已确认需求不符。

独立职责为观察订阅：

| 命令 | 可执行契约 |
| --- | --- |
| `/focus <序号>` | 选择普通消息路由目标，任务回执及必要交互继续关联其原任务；不自动订阅全部桌面主动任务的输出 |
| `/attach <序号>` | 订阅该原生会话中桌面主动发起任务的后续进展、结果及交互；不改变普通文本的 focus，不重放历史结果，不创建或迁移 thread |
| `/detach` | 取消当前观察订阅；不清空 focus、不取消任务、不关闭终端；桥接已接收任务的结果与必要审批继续按原关联投递 |

首版每个微信绑定最多一个独立观察订阅，重复 attach 同一目标幂等；attach 另一目标时明确回显替换的订阅。绑定失效或不支持原生事件订阅时返回错误并保留原状态；未收到正式订阅确认不得回复成功。

示例：focus B 项目，attach A 会话；普通文本发往 B，同时收到 A 桌面任务的进展。detach 后普通文本仍发往 B。状态分别显示“执行目标”和“观察订阅”，避免把观察当作控制权迁移。

曾评估把 attach／detach 作为 focus／unfocus 的兼容别名；本人已选择独立观察订阅，因此不采用该替代方案，detach 不清除普通消息目标。

原生事件订阅和两端交互仍依赖 W02／W03 已验证能力；完整命令实现还须独立验证。当前进度只见 ROADMAP。

## HOST01：宿主生命周期契约

本人于 2026-10-29 确认以下目标并要求开工，当前验收状态见 ROADMAP：合法 `/sessions`、`/cd`、`/new` 在满足参数和目录前置条件后，可按需拉起未运行的 iTerm2；帮助、项目列表、状态及普通消息不触发拉起。应用主动退出后后台只等待重新运行，不反复打开应用或弹授权。

宿主连接断开不能阻塞微信通道；会话命令及时给出进展及有界结果。重新启动应用后自动重连、失效旧数字列表并完整核验当前终端与原生身份。只有准确原会话可恢复旧选择，不能按标题或目录猜测；原会话消失时明确提示重新选择，未知创建与任务不重放。

宿主连接代次与原生运行时代次分别处理：原生连接仍有效的准确任务／观察订阅继续处理事件和交互；这不授予新任务派发资格。原生连接失效使其旧交互失效。完整时限、自测和真实验收遵循[HOST01 清单](../goals/20261029-1038-host-lifecycle-recovery.md)。

## REC01：准入状态与本地处置

施工契约：/status 与 /status <task-id> 分别显示任务结果和占用，等待项列出具体阻塞者、最后核验和下一步；离线显示最后记录及失效说明，不冒充刚刚核验。/stop 对 received 保留本地撤销，不能将 unknown 直接当未提交取消。

计划本地 CLI admission-report 与 admission-release：默认只读，release 的 apply 必须准确任务、处置理由和报告 revision／确认摘要；消费者维护锁下执行原生只读核验和审计。无活动证据不足时拒绝，不提供全量解锁或 force；释放不改写 unknown、不调用原生执行、不发微信。实际实现及上线状态见 ROADMAP。

## 微信独立选择原生会话

本人于 2026-11-07 明确要求实施以下行为：微信普通消息的目标由微信显式选择决定。桌面窗口焦点、标签切换或同一 Codex 进程内的 `/new`／恢复操作不自动改变微信选择。显式 `/focus`、`/cd`、`/new` 按各自契约改变目标；`/send` 只影响该条任务，`/sessions`／`/unfocus` 仍按原契约退出输入聚焦。已经接收的任务始终关联接收时固定的原 thread。

TGT02 开工后采用原生身份契约：既有对话由注册 cwd 限定的后台列表、原生代次、准确 thread／native session、加载状态及正式订阅确认接入，不要求证明它当前显示在哪个窗口，也不读取页脚／标题来选身份。原终端来源可选，不伪造 endpoint。新建可见会话仍须自有启动进程回执与唯一原生握手，缺失或歧义时不 ready；实现与验收状态见 ROADMAP，不能将本契约视作正式 0.1.7 已去除首次显示依赖。

原目标卸载、原生断连或身份变化时，拒绝派发并提示微信；窗口或进程退出只触发重新核验原生可用性，不自动换目标，也不保证原 thread 仍能执行。不从存档恢复、复制历史或另建替代会话。原生接入失败或提交结果未知时按原协议说明状态，不把有 ID 或 loaded 当作执行成功，不重放未知输入。[TGT01 验证](validation/wechat-independent-target.md)保留历史验收，[原生身份契约](native-session-identity.md)说明本轮实现边界。
