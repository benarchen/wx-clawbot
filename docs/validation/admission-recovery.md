## 候选设计与实现边界

schema 5 新增以下程序自有结构，旧库仍需显式迁移：

| 对象 | 字段及职责 |
| --- | --- |
| `task_occupancy` | task_id、waiting／holding／released、revision、reason、evidence、checked_at、updated_at；独立于任务结果 |
| `occupancy_audit` | task_id／revision 唯一的追加事件；记录占用状态、原因、必要结构化证据及时间 |
| `admission_waits` | 阻塞者、原因、首次等待、最后核验、是否升级提示；跨重启去重 |
| `occupancy_active` | waiting／holding 部分索引；准入只读取完整的有界活动视图 |
| `occupancy_history` | 已释放历史按任务 ID 分页，不将历史全部载入准入路径 |

新意图 waiting；真正派发前 holding；终态或证据充分的异常处置变为 released。释放旧 unknown 只改占用与审计。启动、断连、迟到事件、终态和迁移均须维护该不变量。占用重新出现不删除原释放审计。

历史核验只读原始 thread／client／turn 与完整队列，检查原生身份、cwd、终态及已知工具状态，前后复核。查询不全、缺少身份、重复 client、运行／排队、已知工具未结束、提交在途、来源或 revision 变化均保守拒绝。不会用空队列、idle、终端退出或时间独立释放占用，也不能证明未登记的后台系统子进程全部退出。

查询范围决策：占用核验只查找全部待核验的准确原 turn，不为释放占用扫描整条线程的无关旧历史。找到全部关联终态后即可结束历史查找，再复验线程和完整队列；查找过程中出现重复关联仍拒绝。不能把这一有界占用证据用于宣称全历史 client 唯一或更新独立任务结果；后者继续走原有更严格的结果对账。

`admission-report --task-id <id>` 和 `admission-release --task-id <id>` 默认只读。实际 apply 需要准确报告摘要、处置理由、单消费者维护锁和重新获取的原生证据，不提供 force。该本地操作不重放任务，不发送微信，不恢复会话；在线自动核验使用同一证据判定和持久化释放函数。
