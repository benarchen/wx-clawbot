## 实现与不变量

| 改造 | 实际方案 | 保持的边界 |
| --- | --- | --- |
| 原生事件 | 仅在入队前过滤明确不用且无 request ID 的文本增量 | response、审批／追问／resolved／终态、未知 server request 不丢弃 |
| 结果工作 | 最多 2 个正在处理，活动及等待身份共最多 128 份，同 thread 保序，当前活动去重 | 工作只读结果，不重新提交；真实过载仍安全失效并对账 |
| CPU 隔离 | 至少 65536 字符使用临时 Python 子进程，每消费者最多 2 个、20 秒截止，输入／输出各最多 8 MiB；小结果用线程 | 无常驻服务或新依赖；事务外渲染；取消后回收实际工作才释放槽位 |
| 订阅 | 本地事件引用只等待本 thread 的退订，不受其他 thread 慢 RPC 阻塞 | 不授予新派发资格，不复活已释放订阅，不改交互赢家 |
| 端点 | 精确查目标 terminal 并重读进程／TTY，保留前后 footer 和 native 复验 | 不以缓存替代派发门禁，不扫描无关端点验证一个目标 |
| 账本 | 显式 schema 4：`reply_task_kind`、`task_native_turn`、`task_active` 三个索引 | 无业务列变更；备份、绑定／消费者锁、FULL 和不重放保持 |
| 发送 | 相关写入成功提交后唤醒，查询前清标记，最多 5 秒兜底 | 不漏唤醒；cursor-only／失败事务不唤醒；unknown 不自动重试，HTTP 串行 |
| Markdown | 无相关语法时保守快速返回；子进程返回源切片，父进程附加前缀 | 旧 outbox 不重渲染；代码／URL／空白／围栏／分段 payload 逐字等价 |

`results.py` 管有界结果调度，`render_worker.py` 只解析 stdin 显示数据并输出有界 JSON，不读取认证／项目文件／原生状态，不执行文本。实现及正式自测入口均在下述补丁中。

## 测量口径与失败定位

同机 Python 3.14、同精确依赖、固定 seed `20261031`，原版／候选独立进程及合成账本。普通渲染／SQL 预热 1 次、至少 15 个样本，最大容量预热 1 次、5 个样本；记录原始值、median／nearest-rank p95／max、源码摘要及查询计划。成对顺序执行，不混入 profile 时间。

第一轮进一步检查发现早期控制样本发生于大结果完成以后，不能当作并发通过。加入重叠断言和 CPU 压力后，线程实现 p95 为 1412.97 毫秒，100 个样本仅 16 个发生于结果仍活动期间，A01 失败。由此增加临时 CPU 子进程，不放宽延迟门槛。

最终并发用例把同一最大输入实际计算 5 次，延长 CPU 压力窗口而不改变输出；100 次追问必须全部发生于结果尚未结束期间。该压力与普通单次计时分开。原普通 15 秒收尾预算不足以覆盖 5 次计算，压力总收尾截止设为 120 秒，单次子进程仍为 20 秒。

内存分别记录父／子进程；新进程运行实际异步路径，报告父峰值加最大已退出子进程峰值的保守合计，不能漏计子进程。并行两槽位另有确定性测试；短时稳定分配量不能证明长期无泄漏。

## 自动验证与真实边界

- 原版有效失败：追问被长结果挡住、1 万条 delta 导致 QueueFull；修正后通过。另测同 thread 保序、去重、过载、存储异常传递和取消回收。
- 2／10／30／100 端点计数；require 只检查目标。PID 复用、TTY／footer／cwd／runtime／session 失配、模态隐藏和退出的拒绝回归保持。
- schema 1／2／3 至 4、异常版本／绑定／结构、活消费者拒绝、DDL 后回滚、备份超时及重复升级；10 万任务＋10 万回执升级逐表内容和备份摘要一致。
- 实际 Unix peer、`poll`、`Execution`、SQLite、交互和 Sender 串接，100 个准确追问／答复、1 万增量、最大结果、120 秒混合负载和 60 秒空闲。微信 API 为本地 fake，不冒充 API accepted 或本人收件。
- 14 类 fixture、200 个固定种子混合样例、6 类容量及真实子进程的 CRLF 围栏／裸 CR／前缀逐字对照。
- 完整 537 项离线回归通过；真实 socket 测试经获准权限运行。最终源码、编译、依赖、148 处本地链接／锚点、补丁及公开内容检查写入机器数据；独立基线应用公开补丁后全部候选源码／测试逐字重建，28 份前后摘要一致。

真实 iTerm2 SDK／原生 0.166.0 冒烟使用一个自有窗口、最多两个标签。首次握手完成但 footer 无 Session ID，保留未核验；本人明确授权只临时添加 `session-id`、保留原 5 项并恢复。旧自有标签在唯一握手 completed／idle 核对后关闭，新一轮重新登记身份。

新一轮两终端通过 footer、进程代次、runtime／session／thread 复验；原生队列完成真实长文本及一次固定 `choice` 追问。测试客户端只向准确本轮 request 回答 `PERF01_BETA`，原生确认 resolved，两任务 completed。回执由本地 fake 接收，真实微信发送为 0。

实际模型输出长度不作为最大容量成绩；大结果子进程分支另通过真实 OS 子进程的离线字节／资源和全链路压力验证，未新增原生 API。SDK／原生证据与显示 CPU 分支分别记载，不冒充新做微信显示／复制验收。

自有 thread 的 Plan 设置已精确恢复，自有标签已核对并关闭，临时全局配置逐字恢复。日常配置、凭据、启动项和运行源码摘要保持，真实账本的 81 条任务／448 条回执保持；历史 unknown 2 不重放。
